# 2026-08-27 - 단일 적 NavMesh 추적 기반 구현

## 목적

군중 시스템을 추가하기 전에 Enemy 한 마리가 서버 권한으로 플레이어를 선택하고 UE NavMesh를 따라 추적하는 최소 연결을 만든다.

## Codex 변경 사항

- `ADetourCrowdAIController`를 상속하는 `ABHCrowdEnemyAIController`를 추가했다.
- 서버에서 현재 살아 있는 Player-controlled `ABHHeroCharacter` 중 가장 가까운 대상을 선택한다.
- 선택한 대상에 `MoveToActor`를 요청하며 정지 거리는 기본 150cm다.
- 0.5초마다 타깃 유효성과 이동 상태를 확인한다.
  - 목표가 바뀌었을 때 새 경로를 요청한다.
  - 이동이 끝났지만 목표가 정지 거리 밖으로 벗어났을 때 이동을 다시 요청한다.
  - 이동 중에는 매 검사마다 경로를 다시 요청하지 않는다.
- 타깃을 Focus로 설정하고 `BHEnemy`가 Controller Desired Rotation을 사용하도록 연결했다.
- `BHEnemy`의 기본 AI Controller를 `ABHCrowdEnemyAIController`로 교체했다.
- 실제 AI 테스트 단계에 들어왔으므로 새 C++ 기본값에서 `bWalkLeftForAnimationPreview`를 false로 변경했다.

## 사용자 에디터 작업

1. C++ 변경을 반영한 뒤 `BP_Enemy_Base`를 연다.
2. Class Defaults에서 다음을 확인한다.
   - `AI Controller Class`: `BHCrowdEnemyAIController`
   - `Auto Possess AI`: `Placed in World or Spawned`
   - `Walk Left for Animation Preview`: 꺼짐
3. 테스트 맵에 `NavMeshBoundsVolume`을 배치해 적과 플레이어 사이의 이동 가능 공간을 덮는다.
4. 뷰포트에서 `P` 키를 눌러 바닥에 녹색 NavMesh가 표시되는지 확인한다.
5. `BP_Enemy_Base` 한 마리를 NavMesh 위에 배치한다.
6. PIE에서 다음을 확인한다.
   - 적이 플레이어 방향을 바라보며 접근한다.
   - 약 150cm 거리에서 멈춘다.
   - 플레이어가 멀어지면 추적을 재개한다.
   - Enemy AnimBP의 `GroundSpeed`, `Direction`, `bHasAcceleration`이 이동에 따라 바뀐다.

기존 Blueprint가 `bWalkLeftForAnimationPreview = true` 값을 이미 저장했다면 C++ 기본값 변경이 자동 반영되지 않을 수 있으므로 반드시 직접 끈다.

## 후속 진단: 추적 중 Jog 상태로 전환되지 않음

### 확인된 구조

- `ABP_Guardian` 에셋은 `BHEnemyAnimInstance`를 부모로 사용한다.
- 공용 C++ AnimInstance는 매 업데이트에서 `GroundSpeed`, `Direction`, `bHasAcceleration`을 계산한다.
- `GroundSpeed`는 실제 수평 Velocity 크기이고 `bHasAcceleration`은 Character Movement의 현재 가속도 유무다.

### 권장 전환 기준

Locomotion 상태는 실제로 움직이는지를 표현하므로 가속도보다 속도를 기준으로 판정한다.

- `Idle → Jog`: `GroundSpeed > 5.0`
- `Jog → Idle`: `GroundSpeed <= 5.0`

`bHasAcceleration`만 전환 조건으로 사용하면 AI가 이미 속도를 가지고 움직이는 동안 가속도가 0이 되거나 감속·경로 보정 중일 때 Idle로 잘못 판정할 수 있다. 이 값은 추후 출발/정지 연출의 보조 조건으로 사용한다.

Transition Duration이 이미 0.2초인데도 끊긴다면, Duration보다 상태 전환 반복을 먼저 확인한다. `Idle → Jog = bHasAcceleration`, `Jog → Idle = !bHasAcceleration` 구성에서는 Detour 경로 보정 중 값이 흔들릴 때 0.2초 블렌드가 끝나기 전에 반대 전환이 다시 시작될 수 있다.

PIE Debug Filter에서 상태가 빠르게 왕복하는지 확인하고, 우선 다음 속도 조건으로 교체한다.

- `Idle → Jog`: `GroundSpeed > 10`
- `Jog → Idle`: `GroundSpeed < 5`

상태가 안정적으로 유지되는데도 포즈가 튄다면 Duration을 테스트 목적으로 0.5초까지 올린다.

- 0.5초에서도 전혀 차이가 없음: 반대 방향 Transition의 설정, Blend Logic, 실제로 실행 중인 ABP 인스턴스를 확인한다.
- 블렌드는 보이지만 자세가 꺾임: Idle/Walk의 Root·Pelvis 기준 포즈 또는 리타게팅 결과를 Blend Space Preview 중간 지점에서 비교한다.

### Idle → Jog는 부드럽지만 Jog → Idle만 끊기는 경우

현재 `Guardian_BS`에는 Idle 샘플이 포함되어 있다. 별도 `Idle`/`Jog` 상태를 유지하면서 `Jog` 상태 안에서 이 Blend Space를 사용하면 다음과 같은 이중 전환이 발생할 수 있다.

```text
GroundSpeed가 0으로 변경
  → Jog 상태 내부 Guardian_BS가 즉시 Idle 샘플 출력
  → 이후 Jog → Idle State Transition 실행
```

이 경우 State Transition Duration이 0.2초여도, Transition이 시작되기 전에 Jog 상태의 출력 포즈가 이미 Idle로 바뀌어 끊겨 보일 수 있다. `ABHCrowdEnemyAIController`도 정지 거리 안에서 `StopMovement()`를 호출하므로 GroundSpeed가 빠르게 0이 될 수 있다.

Idle/Jog 상태를 유지할 때의 권장 구조는 다음과 같다.

- `Idle` 상태: Idle Sequence
- `Jog` 상태: Idle 샘플이 없는 `Guardian_Jog_BS` 또는 Jog Sequence
- `Idle → Jog`: `GroundSpeed > 10`, Duration 0.2
- `Jog → Idle`: `GroundSpeed < 5`, Duration 0.2

최소 수정으로 먼저 확인하려면 `Guardian_BS`의 GroundSpeed 축 `Smoothing Time`을 0.2로 설정한다. 근본적으로 상태를 분리해 유지할 계획이라면 원본 Blend Space를 복제해 Jog 전용으로 만들고 Idle 샘플을 제거하는 편이 역할이 명확하다.

또한 두 방향 Transition은 서로 다른 Asset이므로 `Jog → Idle` 화살표 자체의 `Blend Logic`, `Duration`, `Mode`를 별도로 확인한다.

### PIE 진단 분기

1. PIE 실행 중 `ABP_Guardian`을 열고 `Debug Filter`에서 실제 `BP_BHEnemy` 인스턴스를 고른다.
2. 이동 중 `GroundSpeed` 값을 확인한다.
   - `GroundSpeed = 0`: Mesh의 Anim Class, ABP Parent Class 또는 Debug 대상 인스턴스가 잘못된 경우를 먼저 확인한다.
   - `GroundSpeed > 0`인데 Idle 유지: State Machine의 `Idle → Jog` 전환 조건을 위 속도 기준으로 수정한다.
   - Jog 상태인데 포즈가 Idle: Blend Space Player의 `GroundSpeed` 핀 연결과 샘플 배치를 확인한다.
   - Jog 포즈가 한 번 재생되고 멈춤: Blend Space Player의 `Loop`를 확인한다.
