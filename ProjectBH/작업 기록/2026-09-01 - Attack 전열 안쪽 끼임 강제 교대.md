# Attack 전열 안쪽 끼임 강제 교대

## 문제

Attack Slot을 점유한 Enemy와 Player 사이에 Wait·Holding·Pending Enemy가 끼면, 안쪽 Enemy는 전열에 막혀 빠져나오지 못하고 기존 Attack 점유자는 자리를 유지해 둘 다 정체될 수 있다. Player가 크게 이동하기 전까지 상태가 풀리지 않는 것이 핵심 문제다.

## 적용 규칙

1. Player와 각 Attack 점유자를 이은 선분 주변에서 비Attack Enemy를 찾는다.
2. 좌우 `70 cm`, 양 끝점 여유 `20 cm`, 높이 차이 `100 cm` 안에 있는 조합만 후보로 인정한다.
3. 여러 후보 중 끼인 Enemy와 가장 가까운 Attack 점유자를 선택한다.
4. 동일 후보가 `0.35초` 유지되고 `20 cm` 이상 전진하지 못했을 때 끼임으로 확정한다.
5. 끼인 Enemy가 Attack Slot을 받고 기존 점유자는 끼인 Enemy의 Wait·Holding Slot로 후퇴한다. Pending 침입자와 교대하면 기존 점유자가 Pending으로 내려간다.
6. 기존 점유자와 해당 Attack Slot에 `1초` 재교대 제한을 적용한다.

공격 또는 회복 중인 Attack 점유자는 Montage를 강제 중단하지 않는다. `Chasing`으로 돌아온 뒤에도 조건이 유지될 때만 교대한다.

## 이동 예외

새 Attack 점유자가 Combat Core 안쪽에 있더라도 받은 Slot이 현재 위치보다 바깥의 같은 방사 방향에 있으면 그 Slot으로 곧바로 이동한다. 기존처럼 먼저 전체 CoreEscape 종료 반경까지 후퇴했다가 Attack Slot으로 되돌아오는 우회는 하지 않는다.

## 조정값

`CombatEngagementSlotComponent`의 `Combat | Core Intrusion Handover`에서 조정한다.

| 항목 | 기본값 | 의미 |
| --- | ---: | --- |
| Enable Core Intrusion Handover | true | 기능 전체 On/Off |
| Core Intrusion Corridor Radius | 70 cm | Player–Attack 점유자 선분 좌우 후보 폭 |
| Core Intrusion Endpoint Padding | 20 cm | 선분 양 끝의 오검출 제외 범위 |
| Core Intrusion Height Tolerance | 100 cm | 다른 층 후보 제외 높이 |
| Core Intrusion Stable Time | 0.35 s | 끼임 확정 시간 |
| Core Intrusion Progress Distance | 20 cm | 이 거리 이상 이동하면 정체 타이머 초기화 |
| Core Intrusion Handover Cooldown | 1.0 s | 교대 직후 역교대 방지 시간 |

## 검증 상태

- `ProjectBHEditor Win64 Development` UHT, 컴파일, 링크 성공.
- PIE에서 Wait·Holding·Pending 각각의 교대와 후퇴 목적지를 확인해야 한다.
- Attack 점유자가 공격·회복 중일 때 Montage가 끊기지 않는지 확인해야 한다.
- 교대 직후 `1초` 안에 원래 점유자가 같은 Slot을 다시 빼앗지 않는지 확인해야 한다.
- 단순 통과 중인 Enemy가 `0.35초` 전에 빠져나오면 오검출되지 않는지 확인해야 한다.
