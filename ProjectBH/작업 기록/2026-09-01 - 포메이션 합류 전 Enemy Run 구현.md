# 포메이션 합류 전 Enemy Run 구현

## 목표

- Enemy가 플레이어를 추격해 최초 포메이션 Slot에 도착하기 전까지 Run을 사용한다.
- 포메이션에 한 번 합류한 뒤에는 Wait·Holding·Attack 이동과 Reform에서 기존 Locomotion 로직을 사용한다.
- AnimBP 바이너리 작업은 사용자가 직접 수행할 수 있도록 C++ 출력값과 연결 절차를 분리한다.

## 구현 규칙

Enemy의 `bHasJoinedFormation`은 예약 여부가 아니라 실제 도착 여부를 나타내는 복제 상태다.

- 최초 예약 Slot의 `SlotAcceptanceRadius` 안에 들어오면 `true`로 고정한다.
- Slot 승격, 교환, Reform, 피격, 일시적인 경로 실패에서는 유지한다.
- 타깃 변경·상실, 전투권 완전 이탈, 사망·AI 해제, Object Pool 재활성화에서는 `false`로 초기화한다.

AnimInstance의 최종 Run 조건은 다음과 같다.

```text
bShouldUseRunLocomotion
    = bIsChasing
    && bShouldMove
    && !bHasJoinedFormation
```

`bShouldMove`는 기존처럼 GroundSpeed의 10 cm/s 진입, 5 cm/s 이탈 히스테리시스를 사용한다.

## 에디터 작업

`ABP_Guardian`의 Locomotion State 내부에 `Blend Poses by Bool`을 두고 다음과 같이 연결한다.

- False Pose: 기존 `Guardian_BS`
- True Pose: 반복 재생 Run Sequence
- Active Value: `bShouldUseRunLocomotion`
- Blend Time: 우선 0.15~0.2초

기존 State 전환과 `Guardian_BS` 샘플은 변경하지 않는다.

## 검증 상태

- `ProjectBHEditor Win64 Development` UHT, 컴파일, 링크 성공.
- 실제 Run 전환과 포메이션 합류 후 기존 Locomotion 복귀는 ABP 연결 후 PIE 검증이 필요하다.
