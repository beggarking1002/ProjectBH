# 2026-08-28 - 몬스터 이동 계약 6개 항목 강화

## 목적

[[몬스터 이동 시스템 규칙]] 감사에서 우선순위로 정한 여섯 문제를 한 번에 보강한다.

1. Attack 거리 기준 통일
2. 공격·회복 중 Reform 고정
3. 타깃 고정 시간과 도달 가능성
4. 일시 실패 시 Queue 우선권 보존
5. Pending 분산 대기 위치
6. Admission 혼잡 점수

## 구현 결과

### 1. Attack 거리 단일 기준

- `UCombatEngagementSlotComponent::GetMaximumAttackSlotDistance()`를 유일한 계산 지점으로 추가했다.
- 계산식은 `AttackStartRange - 실제 AI Controller SlotAcceptanceRadius`다.
- 기본값은 `150 - 15 = 135 cm`다.
- 다음 경로가 모두 같은 값을 사용한다.
  - Runtime Attack 직접 예약
  - Initial Attack Admission
  - Wait→Attack 승격
  - Attack 교착 시 Wait 후보 교대
- NavMesh 투영으로 Attack Slot이 135 cm 밖으로 밀리면 해당 Slot을 후보에서 제외한다.

정확한 판정 계약은 다음과 같다.

- 거리는 Hero Actor 위치와 **NavMesh 투영이 끝난 Slot 위치** 사이의 2D 평면거리다.
- 경계값은 포함한다. 즉 기본값에서는 `거리 <= 135 cm`가 유효하다.
- `AttackStartRange <= SlotAcceptanceRadius`이면 안전 거리는 0 cm로 clamp된다.
- `SlotAcceptanceRadius`는 해당 Enemy를 실제로 소유한 `ABHCrowdEnemyAIController` 인스턴스의 값이며 Controller를 찾지 못하면 15 cm를 사용한다.
- Attack Ring 기본 반경 125 cm는 안전 거리 135 cm 안에 10 cm의 투영 여유를 둔 구성이다.

### 2. 공격·회복 중 Reform 고정

- Attack Ring Reform에서 `Attacking` 또는 `Recovering` Enemy의 현재 Slot 인덱스를 고정한다.
- 잠긴 Slot은 다른 Enemy의 재배정 후보에서 제외한다.
- `Chasing` Attack Enemy만 남은 Attack Slot 사이에서 재배정한다.
- Wait와 Holding 역할 내 Reform은 기존대로 유지한다.
- 여기서 고정되는 것은 월드 좌표가 아니라 **Attack Ring 안의 Slot 인덱스**다. Hero가 이동하면 같은 인덱스의 월드 위치는 Hero를 따라 이동한다.

### 3. 안정적인 타깃 선택

`ABHCrowdEnemyAIController`에 다음 기본값을 추가했다.

| 항목 | 값 | 역할 |
| --- | ---: | --- |
| `MinimumTargetHoldTime` | 2초 | 현재 타깃 최소 유지시간 |
| `TargetSwitchDistanceAdvantage` | 200 cm | 교체 후보가 추가로 가까워야 하는 거리 |
| `TargetNavProjectionExtent` | 100, 100, 250 cm | 플레이어 위치 NavMesh 투영 범위 |

- Player Hero 위치가 NavMesh에 투영되고 완전한 비부분 경로가 존재해야 후보가 된다.
- 현재 타깃이 도달 가능하면 2초 동안 다른 플레이어로 바꾸지 않는다.
- 2초 뒤에도 다른 플레이어가 최소 200 cm 가까울 때만 교체한다.
- 현재 타깃이 무효이거나 도달 불가능하면 유지시간을 무시하고 즉시 다른 도달 가능한 플레이어를 찾는다.
- 공격·회복 중에는 기존처럼 타깃 탐색을 중단하므로 고정 Attack Target과 Focus가 유지된다.

타깃 거리 비교는 Enemy와 Hero Actor 위치의 2D 직선거리를 사용한다. 최초 선택은 도달 가능한 Hero 중 가장 가까운 대상이며, 선택 시점에 유지시간이 0초로 초기화된다. `Held` 디버그 값은 남은 시간이 아니라 선택 후 경과시간이다. 서버가 기본 0.5초마다 재평가하며, 공격·회복 도중 타깃이 무효가 되는 예외 처리는 이번 범위에 포함하지 않았다.

### 4. Queue Sequence 보존

- `ReleaseSlot()`에 Queue 보존 선택을 추가했다.
- 다음 일시 실패는 물리 Slot만 반납하고 기존 Sequence를 유지한다.
  - Reservation Invalid
  - Attack Range Mismatch
  - Attack Start Failed
  - Move Request Failed
  - Path Following Failed
  - Stalled
- 타깃 변경·소실, UnPossess, 경직과 사망은 기존처럼 Queue 등록을 제거한다.
- 재획득 때 Slot Component가 잠시 `nullptr`인 경우를 타깃 변경으로 오판해 실패 Slot 제외를 지우던 흐름도 함께 수정했다.

Sequence는 Hero 한 명의 Combat Engagement Slot Component 안에서 단조 증가하며 재사용하지 않는다. 일시 실패 보존은 같은 Hero의 Queue에 재진입할 때만 유효하다. 다른 Hero로 타깃을 바꾸면 기존 Queue에서 제거되고 새 Hero의 Queue에서 새 Sequence를 받는다. 반복되는 일시 실패에는 현재 별도의 최대 보존시간이 없다.

### 5. Pending 분산 대기

Holding 16개를 초과한 Enemy는 더 이상 현재 위치에서 정지하지 않는다.

| 항목 | 값 |
| --- | ---: |
| `PendingRingRadius` | 700 cm |
| `PendingSlotsPerRing` | 24 |
| `PendingRingSpacing` | 150 cm |
| `PendingRingAngleOffset` | 7.5° |

- 미예약 Queue Sequence를 기준으로 Pending 인덱스를 만든다.
- Pending 0~23은 700 cm Ring, 24~47은 850 cm Ring을 사용한다.
- 위치는 NavMesh에 투영한다.
- Controller의 Slot Type에 `Pending`을 추가해 일반 Move, Combat Core 우회, Watchdog과 디버그를 그대로 사용한다.
- 앞선 Pending이 Holding으로 승격되면 나머지 Pending 인덱스가 당겨지고 새 목적지로 갱신된다.
- Pending 디버그 위치는 청록·초록색 작은 구체로 표시한다.

Pending Ring의 중심은 현재 타깃 Hero의 Actor 위치다. Attack·Wait·Holding 예약이 없는 Queue Entry만 Sequence 오름차순으로 다시 번호를 매기며 `Q` 디버그 표기는 Pending 수를 뜻한다. 기본 NavMesh 투영 범위는 Slot Component의 `NavProjectionExtent = (50, 50, 200) cm`, 최종 위치 도착 허용오차는 Controller의 `SlotAcceptanceRadius = 15 cm`다.

### 6. 혼잡 인식 Admission

- 완전한 Nav 경로의 Path Point를 사용해 후보 경로 주변의 같은 층 Queue Enemy를 센다.
- 기본 반경 `110 cm` 안의 Agent 한 명당 경로 점수에 `200 cm`를 더한다.
- Agent 하나가 여러 경로 선분에 걸쳐 있어도 한 번만 계산한다.
- 다음 세 중앙 선정이 `Nav Path Length + Congestion Penalty`를 사용한다.
  - Initial Attack Admission
  - Runtime Wait→Attack 승격
  - Attack 교착 시 Wait 후보 교대
- 이 점수는 Detour Crowd의 실제 미래 움직임을 시뮬레이션하지 않는 저비용 근사치다.

혼잡 계산은 Requester 자신을 제외한 **해당 Hero의 전체 Queue Enemy**를 대상으로 한다. 각 Agent 중심과 Nav Path 선분의 2D 거리가 110 cm 이내이면 한 번만 센다. 두 Agent 캡슐 반높이 중 큰 값보다 Z 차이가 크면 다른 층으로 제외한다. 점수가 1 cm 이내로 같으면 Queue Sequence가 오래된 후보가 우선한다.

## 사용자 PIE 검증

### 공통 준비

1. Unreal Editor를 다시 열고 기본 검증 맵인 `FeatureDevMap`을 연다.
2. `/Game/Enemy/BP_BHCrowdEnemyAIController` Class Defaults에서 `AI|Pursuit`를 확인한다.
3. `/Game/PlayerCharacter/BP_BHHeroCharacter`의 Combat Engagement Slot Component에서 `Combat|Pending Queue`와 `Combat|Engagement Admission`을 확인한다.
4. C++ 기본값으로 먼저 시험한다. Blueprint에 노란색 되돌리기 화살표가 표시된 값은 로컬 override이므로 화살표를 눌러 C++ 기본값으로 되돌릴 수 있다.
5. Pending 700 cm Ring까지 녹색 NavMesh가 덮도록 `NavMeshBoundsVolume`을 넓힌다.
6. 기본값 `Draw Crowd Debug`와 `Draw Debug Slots`가 켜져 있는지 확인한다. Enemy 머리 위 `Target`, `Held`, Slot, `Seq`, `Last`와 Hero 머리 위 `A/W/H/Q`를 성공 판정에 사용한다.

### A. Attack 거리

1. Attack Ring 반경 125 cm, AttackStartRange 150 cm, Slot Acceptance 15 cm로 시작한다.
2. 투영된 Attack Slot이 135 cm 안이면 네 Slot이 정상 배정되는지 확인한다.
3. 장애물을 이용해 특정 Slot을 135 cm 밖으로 투영시켰을 때 해당 Slot이 비어 있고 `AttackRangeMismatch` 반복이 발생하지 않는지 확인한다.

### B. Reform 잠금

1. Enemy 한 명이 공격 또는 회복 중일 때 플레이어를 Reform 기준 500 cm 이상 이동시킨다.
2. 해당 Enemy의 Attack Slot 인덱스가 유지되는지 확인한다.
3. 다른 `Chasing` Attack Enemy만 남은 Slot에 재배정되는지 확인한다.

### C. 타깃 안정성

1. 플레이어 두 명으로 Listen Server PIE를 시작한다.
2. 두 플레이어가 Enemy에서 비슷한 거리를 유지하며 교차한다.
3. `Target`과 `Held`가 매 0.5초 흔들리지 않는지 확인한다.
4. 두 번째 플레이어가 200 cm 이상 확실히 가까워지고 Held가 2초를 넘긴 뒤에만 교체되는지 확인한다.
5. 현재 플레이어와 Enemy 사이 NavMesh를 끊었을 때 도달 가능한 다른 플레이어로 즉시 바뀌는지 확인한다.

### D. Queue 보존

1. Wait 또는 Holding Enemy의 진행 방향에 다른 Enemy나 임시 Collision Actor를 두고 이동속도 10 cm/s 미만인 상태를 2초 이상 유지한다. Watchdog 기본값은 시간 2초, 최소 진전 20 cm다.
2. `Last:Stalled` 직전과 재획득 후 머리 위 `Seq`가 같은지 확인한다. 반납 직후 한 번의 갱신 프레임에는 `Seq:0`이 보일 수 있다.
3. 해당 Enemy를 경직시키면 Queue에서 빠지고 복귀 후 새 Sequence를 받는지 확인한다.

### E. Pending Ring

1. Enemy 32마리를 배치한다.
2. `A:4 W:8 H:16 Q:4`를 확인한다.
3. Q 4명이 700 cm Ring의 서로 다른 청록·초록 구체로 이동하는지 확인한다.
4. Holding Enemy를 제거해 Pending 최선임자가 Holding으로 승격되는지 확인한다.
5. 나머지 Pending 인덱스와 목적지가 앞으로 당겨지는지 확인한다.

### F. 혼잡 Admission

1. 서로 다른 Attack Slot 후보로 가는 두 경로를 만든다. 한쪽 경로 110 cm 안에는 Queue Enemy를 밀집시키고 반대쪽 경로는 조금 더 길지만 비워 둔다.
2. Hero Combat Engagement Slot Component의 `Admission Congestion Penalty Per Agent`를 0으로 두고 초기 배정 또는 Wait 승격 영상을 기록한다.
3. 같은 배치에서 값을 200 cm로 바꾸고 다시 기록한다. 예를 들어 혼잡 Agent가 2명이면 해당 후보 점수에 400 cm가 더해진다.
4. 각 설정을 같은 시작 배치에서 3회씩 반복한다. Detour 조향의 한 번짜리 우연한 차이를 결과로 간주하지 않는다.
5. 혼잡한 최단 경로만 반복 선택하던 결과가 빈 경로 후보 선택으로 바뀌는지 비교한다. 현재 경로별 점수 자체는 화면에 표시하지 않으므로 영상과 Slot 선택을 근거로 판정한다.

## 현재 한계

- 플레이어 생존·다운·Line of Sight는 아직 타깃 후보 조건이 아니다.
- Pending 위치는 NavMesh 투영 결과가 겹치는 복잡한 지형에서 서로 같은 지점으로 수렴할 수 있다.
- Pending 앞 순번이 승격되면 뒤 Pending의 목적지가 함께 이동한다.
- Pending 위치가 투영·이동 실패해도 Sequence는 유지되지만 같은 순번에서 계산한 위치를 재시도하므로 지형에 따라 실패가 반복될 수 있다.
- 혼잡 점수는 현재 위치의 Agent 수를 사용하며 향후 Detour 속도를 예측하지 않는다.
- 동기 Nav 경로 질의가 늘었으므로 활성 Enemy와 플레이어 수를 크게 확장할 때 프로파일링해야 한다.
