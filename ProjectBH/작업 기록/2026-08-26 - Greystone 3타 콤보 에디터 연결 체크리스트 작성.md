## 2026-08-26 추가 진단: 좌클릭 공격 미재생

- `Saved/Logs/ProjectBH.log`의 2026-08-26 01:01 PIE 기록에서 `LogAnimMontage: Warning: JumpToSectionName Attack_A ... failed for Montage AM_Knight` 및 `Attack_B` 실패를 확인했다.
- 따라서 `IA_BasicAttack` 입력 바인딩과 서버 공격 요청은 실행됐고, `AM_Knight`에 코드가 요청하는 이름의 실제 Montage Section이 없거나 이름이 일치하지 않아 재생 시작 위치를 찾지 못한 것이 직접 원인이다.
- 타임라인 Animation Segment/Notify의 표시는 Section 등록을 대체하지 않는다. `Montage Sections` 패널에서 `Attack_A`, `Recovery_A`, `Attack_B`, `Recovery_B`, `Attack_C`, `Recovery_C`를 등록하고 저장해야 한다.

## 2026-08-26 추가 진단: Section 수정 후에도 포즈 미출력

- Section을 저장한 뒤의 01:07 PIE 로그에서는 이전 `JumpToSectionName ... failed` 경고가 재발하지 않았다. Section 이름 문제는 해소된 것으로 판단한다.
- 그러나 공격이 보이지 않는다면 Montage 재생 포즈가 `ABP_Greystone`의 최종 포즈 경로에 합성되지 않는 것이 다음 직접 원인이다.
- `ABP_Greystone`은 State Machine 바깥에서 `Locomotion State Machine → Slot(DefaultSlot) → Output Animation Pose` 구조여야 하며, `Locomotion_BS`는 내부 `Jog` State에 남긴다. `AM_Knight` Slot Track도 `DefaultSlot`이어야 한다. 또한 캐릭터 Mesh의 Animation Mode와 Anim Class가 각각 `Use Animation Blueprint`, `ABP_Greystone`인지 확인한다.

## 2026-08-26 추가 안내: AnimBP 공격 합성

- 현재 수직 슬라이스는 공격 State Machine을 추가하지 않는다.
- `AM_Knight`는 C++ `PlayAnimMontage`로 재생하므로, `ABP_Greystone` AnimGraph에서 State Machine의 이동 포즈 뒤에 `Slot(DefaultSlot)`을 하나 두어 최종 포즈에 합성한다. `Locomotion_BS`가 든 `Jog` State 내부에는 Slot을 넣지 않는다.

## 2026-08-26 추가 진단: 1회 입력에 3타 전체 재생

- `Attack_A` 시작 후 Montage가 끝까지 순차 재생되는 증상은 `Recovery_A → Attack_B`, `Recovery_B → Attack_C`가 Montage Section의 기본 Next Section으로 자동 연결돼 있을 때 발생한다.
- 콤보 여부는 Recovery 끝의 `AN Combo Branch`가 C++ 입력 버퍼를 확인해 결정해야 한다.
- 따라서 Attack Section만 대응 Recovery로 연결하고 모든 Recovery Section의 Next Section은 `None`으로 둔다.

## 2026-08-26 추가 정리: 현재 콤보 입력 버퍼 규칙

- A/B/C 각 단계는 다음 타격 하나만 예약할 수 있다. 동일 단계에서 여러 번 누른 입력은 중첩 저장하지 않는다.
- A 또는 Recovery_A 중 입력은 B 예약, B 또는 Recovery_B 중 입력은 C 예약이다.
- A 시작 직후의 다중 연타는 B 하나만 예약하므로 C까지 가려면 B가 시작된 뒤 한 번 더 입력해야 한다.

## 2026-08-26 콤보 전환 속도 조정

- 요구: Attack_A→B, B→C에서 공격 중 추가 입력이 있을 때 긴 후딜레이 없이 다음 공격을 시작한다.
- 기존 `AN Combo Branch`는 Recovery 종료 직전이었으므로, 버퍼 입력이 있어도 Recovery 대부분이 재생된 뒤에 다음 Attack이 시작됐다.
- 해결: C++ 입력 버퍼는 유지하고 `Recovery_A/B`의 `AN Combo Branch`를 직전 검 타격 창 종료 직후 또는 Recovery 초반으로 옮긴다.
- 입력이 있으면 Branch 시점에 다음 Attack으로 전환하고, 입력이 없으면 Recovery는 정상 재생 후 Idle로 복귀한다.
- Branch 이후 입력은 다음 타격으로 예약되지 않으므로 최초 조정값은 Recovery 시작 뒤 0.10~0.15초로 둔다.
