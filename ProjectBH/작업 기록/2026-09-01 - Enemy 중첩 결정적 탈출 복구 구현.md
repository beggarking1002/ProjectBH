# Enemy 중첩 결정적 탈출 복구 구현

## 문제

Enemy Capsule은 같은 `EnemyPawn` 채널을 Ignore하지만, 같은 위치나 매우 가까운 위치에 생성·이동한 Detour Crowd Agent 둘은 서로 대칭적인 회피를 반복하며 제자리에서 버벅일 수 있었다. 기존 No Progress Watchdog은 목적지 실패 후 Slot을 교환하거나 반납하는 복구라서, Slot이 없는 추격·스폰 중첩과 물리적 분리 자체를 직접 해결하지 못했다.

## 구현

- `ABHCrowdEnemyAIController`에 Slot 독립 중첩 검사를 추가했다.
- 실제 Capsule 반지름과 Z 높이 차로 중첩을 판정한다.
- Combat State와 Slot 종류를 기준으로 자리를 지킬 Enemy와 양보할 Enemy를 고른다.
- 동률은 Unique ID로 한쪽만 양보시켜 대칭 복구를 막는다.
- 정확히 같은 Transform의 집단 스폰은 Unique ID 기반 Golden Angle로 방향을 분산한다.
- 양보 Enemy는 주변 여유가 큰 8방향 후보를 NavMesh에 투영하고 완전한 경로가 있는 짧은 탈출 지점을 선택한다.
- 탈출 중 해당 Agent의 Crowd Obstacle Avoidance와 Separation만 임시 해제한다.
- World·Player 충돌, NavMesh Path Following, 현재 Combat Slot과 Queue Sequence는 유지한다.
- 중첩 해소·목표 도착·`0.75초` 제한 도달 시 Crowd 설정을 복원하고 기존 목표를 즉시 재탐색한다.
- 디버그 문자열에 `Overlap:Escape`, 탈출 목표에 주황색 선과 구를 추가했다.

## 기본값

| 항목 | 값 |
| --- | ---: |
| Overlap Detection Scale | 0.9 |
| Overlap Height Tolerance | 100 cm |
| Overlap Escape Distance | 110 cm |
| Overlap Escape Padding | 20 cm |
| Overlap Escape Duration | 0.75초 |
| Overlap Recovery Cooldown | 0.25초 |

## 검증

- `ProjectBHEditor Win64 Development` 빌드 성공.
- PIE에서 같은 Spawn Point에 2마리와 4마리를 겹쳐 생성해 한쪽만 정지하고 나머지가 서로 다른 방향으로 빠지는지 확인한다.
- Attack Slot 예약자와 Wait Enemy를 겹치게 만들어 Wait 쪽만 주황색 탈출 이동을 하고 Attack 예약이 유지되는지 확인한다.
- Slot이 없는 원거리 Pursuit 중 두 Enemy를 겹치게 만들어 탈출 후 기존 추격을 재개하는지 확인한다.
- 벽·좁은 통로에서는 NavMesh 후보가 없을 수 있다. 이 경우 순간이동하거나 Slot을 임의 반납하지 않고 기존 Watchdog 복구로 내려가는지 확인한다.
