# 2026-08-25 - Greystone 3타 콤보 및 다중 스윕 기반 구현

## 목적

Greystone 검+방패 수직 슬라이스의 평타 범위를 3타 콤보로 확정하고, DataTable 도입 전 사용할 서버 권한 콤보·다중 추적 기반을 구현한다.

## Codex 변경 사항

- 평타 범위를 `Attack_A → Attack_B → Attack_C` 3타 콤보로 확정했다.
- `ABHHeroCharacter`에 서버 전용 콤보 상태, 현재 공격 인덱스, 입력 버퍼를 추가했다.
  - Idle 입력은 `Attack_A`를 시작한다.
  - 콤보 도중 입력은 한 번만 버퍼링한다.
  - 각 Recovery 끝의 `AN Combo Branch`에서 버퍼를 확인해 A→B, B→C만 연결한다.
  - 입력이 없거나 C 이후이면 콤보를 종료한다.
- 기존 단일 전방 구형 Sweep을 `Trace_Sword_Base`, `Trace_Sword_Mid`, `Trace_Sword_Tip`의 이전·현재 위치를 각각 Sphere Sweep하는 다중 추적으로 교체했다.
- 한 `ANS Melee Hit Window` 안에서 적중한 액터를 보관해 중복 피해를 막고, `MaxSwordHitActors`로 관통 가능한 적 수를 제한했다.
- `bStopSwordTraceOnWorld`가 켜져 있으면 World Static/Dynamic 충돌 뒤의 Pawn에는 피해가 적용되지 않게 했다.
- `ANS Melee Hit Window` Notify State와 `AN Combo Branch` Notify를 새 C++ 클래스로 추가했다.
- 이번 단계에서는 DataTable, 스태미나, 방패 밀치기, 피격·사망 로직을 구현하지 않았다. 핵심 3타 콤보 검증 뒤에 추가한다.

## 사용자 에디터 작업

1. 파생 Greystone Skeletal Mesh에 `Trace_Sword_Base`, `Trace_Sword_Mid`, `Trace_Sword_Tip` Mesh Socket을 배치한다.
2. `AM_Knight`에서 `Attack_A → Recovery_A`, `Attack_B → Recovery_B`, `Attack_C → Recovery_C`만 자동 연결되게 한다. 각 Recovery에는 다음 섹션을 연결하지 않는다.
3. 각 Attack의 실제 접촉 구간에 `ANS Melee Hit Window`를 배치한다.
4. 각 Recovery 마지막 프레임 부근에 `AN Combo Branch`를 배치한다.
5. Greystone 플레이어 BP의 `BasicAttackMontage`에 `AM_Knight`, `BasicAttackDamageEffect`에 기존 피해 GE를 지정한다.

`ANS Melee Hit Window`와 `AN Combo Branch`의 세부 배치 절차는 [[Greystone Montage Notify 배치 절차]]에 정리했다.
