# 2026-08-28 - 몬스터 이동 규칙 단일 문서 통합

## 목적

몬스터 이동 규칙이 초기 기획, 개발 가이드, 날짜별 작업 기록과 현행 C++에 흩어져 있어 새 채팅에서 현재 상태와 과거 시도를 구분하기 어려운 문제를 해결한다.

## 작업 결과

- [[몬스터 이동 시스템 규칙]]을 몬스터 이동의 단일 기준 문서로 만들었다.
- 현행 C++을 기준으로 타깃 선정부터 NavMesh, Detour Crowd, Slot, Queue, Admission, 승격, 분산형 Ring 진입, Reform, 교착 복구, 경직·사망과 이동 애니메이션까지 통합했다.
- 각 규칙에 발동 조건, 선정 기준, 성공·실패 결과와 다음 상태를 기록했다.
- 현재 구현, 에디터 조건, 검증 필요, 후속 설계와 폐기된 방식을 구분했다.
- 시체 누적형 Enemy Pool과 벽면 Traversal은 후속 설계이며 아직 구현되지 않았음을 명시했다.
- 롤백된 공용 Attack Approach Gate와 초기 `MoveToActor(Player)` 직행 방식은 현행 규칙에서 제외했다.
- 기존 기획 초안과 Traversal 초안은 삭제하지 않고 역사 기록으로 유지하되, 상단에서 새 기준 문서를 참조하도록 했다.
- NavMesh 개발 가이드와 작업 기록 README에도 새 기준 문서를 연결했다.
- 별도 맹검 독자가 문서 전체를 읽고 지적한 타깃 도달 가능성, 공격 중 Reform, 연속 스폰 Initial 연장, Slot 좌표·동률, Pending 병목과 네트워크 검증의 암묵 조건을 현행 동작 또는 한계로 보강했다.
- Unreal Engine 공식 문서로 NavMesh 시각화, Crowd Manager, RVO·Detour Crowd 배타 사용에 관한 엔진 설명을 확인하고 기준 문서에 연결했다.
- 자체 디버그 카운트를 그대로 합격 근거로 쓰는 순환 검증을 피하도록 독립 Actor Transform·상태 전환 시각 대조 규칙을 추가했다.

## 확인된 현재 불일치

- 일반 Attack Slot 예약은 `AttackStartRange - SlotAcceptanceRadius`를 최대 거리로 사용한다.
- Initial Admission과 Runtime Wait→Attack 승격 검사는 전체 `AttackStartRange`를 사용한다.
- 기본값에서는 Attack Ring 125 cm가 두 조건을 모두 만족하지만, NavMesh 투영이나 반경 조정 시 결과가 달라질 수 있다.
- 이번 작업은 문서 통합만 수행했으며 C++ 동작은 변경하지 않았다.
