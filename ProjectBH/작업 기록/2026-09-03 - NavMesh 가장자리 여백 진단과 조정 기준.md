# 2026-09-03 - NavMesh 가장자리 여백 진단과 조정 기준

## 화면 상태 해석

NavMesh Bounds Volume은 바닥보다 넓게 덮여 있다. 초록 NavMesh가 바닥·절벽·벽의 끝에 닿지 않는 것은 대개 Bounds 크기 문제가 아니라 Recast가 Agent가 추락·벽 관통 없이 설 수 있는 영역만 남기기 위해 가장자리를 안쪽으로 침식하기 때문이다.

Recast는 경계/장애물에서 지정 Agent Radius보다 가까운 영역을 비보행으로 표시한다.

## 먼저 확인할 값

1. `RecastNavMesh-Default` Actor를 선택한다.
2. Details > `Generation`에서 `Agent Radius`, `Agent Height`, `Agent Max Slope`, `Agent Max Step Height`를 확인한다.
3. 현재 Hero C++ Capsule은 반경 `42`, 반높이 `96`이다. Hero와 같은 NavMesh를 사용할 적의 Agent Radius를 이보다 작게 잡으면 실제 Capsule이 가장자리/통로에서 충돌하거나 떨어질 수 있다.
4. Details > `Display`의 `Draw Path Colliding Geometry`를 켠다. NavMesh 입력 충돌이 바닥 끝보다 일찍 끝나는지, 턱/벽이 막는지 확인한다.

## 권장 판단

### AI가 가장자리의 플레이어를 충분히 공격할 수 있다면

NavMesh 가장자리 여백은 정상이다. 줄이지 않는다.

- AI의 `MoveToActor` Acceptance Radius 또는 공격 사거리를 `NavMesh 안전 여백 + 실제 무기 사거리`보다 크게 둔다.
- AI는 가장자리 바로 앞이 아니라 가장 가까운 안전 NavPoly에서 멈춘 뒤 공격한다.

### 실제 Capsule이 안전하게 설 수 있는 바닥인데 NavMesh가 지나치게 후퇴했다면

1. `Agent Radius`가 실제 해당 Agent Capsule 반경보다 과대 설정됐는지 확인한다.
2. 바닥 Static Mesh의 Simple Collision이 시각 바닥 끝보다 안쪽에서 끝나는지 `Draw Path Colliding Geometry`로 확인한다. 그렇다면 Static Mesh의 Simple Collision을 바닥 형상에 맞게 수정한다.
3. 경계가 계단/경사면이면 `Agent Max Step Height`, `Agent Max Slope`를 해당 Agent의 실제 이동 가능 범위 안에서만 조정한다.
4. 끝 모양만 거칠다면 `Cell Size`를 낮춰(예: 10에서 5) 재빌드하고, `Max Simplification Error`를 조금 낮춘다. 이는 경계 정확도를 높이지만 NavMesh 빌드 비용과 폴리곤 수를 증가시킨다.

`NavMeshBoundsVolume`만 더 키우는 것은 현재처럼 이미 바닥을 덮는 경우 해법이 아니다.

## 검증

1. `P`로 NavMesh를 표시한다.
2. `Build > Build Paths`로 재생성한다.
3. `MoveToActor` 목표를 가장자리의 플레이어로 두고, AI가 가장 가까운 안전 위치에서 멈춰 공격 가능한지 확인한다.
4. PIE에서 `show collision`으로 Capsule이 NavMesh 끝과 바닥 경계에서 안전한지 확인한다.
