# 정지 슬롯 점유자 사이 진입 교착 진단

## 현상

- 이동 중인 Enemy가 이미 자신의 Attack/Wait/Holding Slot에 도착해 정지한 Enemy들 사이에서 끼고 멈춘다.
- Detour Crowd Separation과 High Quality Avoidance를 적용한 후에도 재현된다.

## 원인 분석

1. `GetMoveGoalForReservedSlot()`은 현재 직선 경로가 플레이어의 Combat Core를 관통할 때만 Orbit Waypoint를 만든다.
2. Combat Core를 피하는 경로라도 정지한 바깥 링 점유자 사이를 가로지를 수 있다.
3. NavMesh는 이동 가능한 정적 공간만 계산하므로, 스롯에 서 있는 다른 Enemy를 피한 전역 경로를 새로 만들지 않는다.
4. Detour Crowd의 Local Avoidance는 주변 에이전트를 피하는 속도를 선택하지만, 목표 진입로 자체가 정지 에이전트로 닫힌 구조라면 해결할 공간이 없다.
5. Enemy 캡슐끼리 `Block`하는 설정이면 Crowd Steering이 실패했을 때 물리적 교착이 영구화될 수 있다.

## 권장 수정

### 1. 분산형 Ring Ingress Waypoint

- Gate는 다시 사용하지 않는다.
- `Holding -> Wait`, `Wait -> Attack`처럼 안쪽 링으로 승격된 Enemy는 직선으로 목표 슬롯에 들어가지 않는다.
- 먼저 목표 슬롯의 각도와 맞는 바깥 링 진입점으로 이동한다.
- 각도 정렬이 끝나면 방사형으로 안쪽 슬롯에 진입한다.
- 모든 Enemy가 하나의 Gate를 공유하지 않고 자신의 슬롯 각도에 맞는 진입로를 사용하므로 Gate 주변 몰림을 재현하지 않는다.

### 2. Enemy 간 하드 충돌 분리 검토

- Enemy끼리의 간격은 Detour Crowd가 유지하고, 캡슐의 Enemy-Enemy 충돌은 `Overlap` 또는 `Ignore`하는 별도 Object Channel을 검토한다.
- Player-Enemy 충돌과 플레이어의 공격 Trace는 유지해야 하므로 `Pawn` 전체를 무조건 Ignore하면 안 된다.
- 따라서 전용 `EnemyPawn` Object Channel을 두는 방식이 안전하다.

## 튜닝 주의

- Separation Weight를 계속 높이는 것은 근본 해결이 아니다.
- 진입로가 막힌 상태에서 Separation이 강해지면 정지 적도 서로 밀고, 이동 적은 더 크게 좌우로 흔들릴 수 있다.
- 먼저 Ring Ingress Waypoint로 경로 구조를 고친 뒤, 필요하면 EnemyPawn 충돌 채널을 분리한다.

## 검증 기준

- 4마리, 8마리, 12마리로 나누어 검증한다.
- 각 링이 채워진 상태에서 `Holding -> Wait`, `Wait -> Attack` 승격을 의도적으로 발생시킨다.
- 승격된 Enemy가 정지 점유자를 직선으로 관통하려 하지 않는지 Debug Waypoint로 확인한다.
- Stuck Watchdog 발동 횟수와 Spacing Violation 피크를 수정 전후로 비교한다.
