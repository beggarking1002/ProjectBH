# Detour Crowd 군중 검증 1차 구현 및 테스트 계획

## 목표

Combat Engagement Slot 위에서 Detour Crowd가 4~12마리의 접근을 안정적으로 처리하는지 검증한다. 단순히 움직이는 장면을 확인하는 데서 끝내지 않고, 통로·이동 타깃·사망·경직·경로 실패 상황에서도 슬롯이 회수되게 한다. 이동 정체는 2초 누적 후 다음 AI 갱신 안에 복구 행동으로 전환한다.

요청 이해: Codex는 군중 진단·교착 복구·공격자 교대·사망 및 경직 상태의 C++ 기반을 구현하고, 사용자는 테스트 레벨과 피격·사망 애니메이션 에셋을 연결한다. 애니메이션이 아직 없어도 로직 검증이 가능하되, 이후 Montage를 지정하면 같은 상태 진입점을 그대로 사용하도록 설계한다.

## 현재 상태

- Attack Slot 4개와 Wait Slot 8개의 예약 및 이동은 C++로 연결되어 있다.
- 기본 반경은 Attack 125 cm, Wait 300 cm이고 AI 갱신 주기는 0.5초다.
- 경로 탐색 실패, 타깃 소실, UnPossess, Actor 파괴 시 슬롯을 정리한다.
- 이동 요청 후 정체를 감지하는 2초 watchdog과 실패 슬롯 2초 제외를 구현했다.
- 공격 회복 종료 시 슬롯을 반납하고 1초 동안 재진입을 막아 Wait 적에게 승격 기회를 준다.
- Enemy의 `Staggered`, `Dead` 상태와 즉시 슬롯 반납을 구현했다.
- 피격·사망 Montage는 선택 사항이며, 지정하지 않아도 AnimBP가 상태 값을 읽어 표현할 수 있다.

## 구현 결과

### 슬롯과 교착 복구

- 슬롯 반납 사유를 enum으로 관리하고 상태 전환 때만 로그를 남긴다.
- 경로 요청 실패와 Path Following 실패는 즉시 슬롯을 반납한다.
- 정체된 적은 현재 슬롯을 반납하고, 같은 슬롯을 2초 동안 제외한 뒤 다른 슬롯을 요청한다.
- 플레이어와 Enemy 위에 슬롯, 거리, 정체 시간, 마지막 반납 사유를 디버그 문자열로 표시한다.
- 플레이어 위 집계에는 Attack/Wait 점유 수, 실제 공격 상태 수, Wait 공격 위반 수, Capsule 간격 위반 수를 표시한다.

### 공격자 교대

- 공격과 회복 중에는 Attack Slot을 유지한다.
- 회복이 끝나면 슬롯을 반납하고 `AttackSlotReentryDelay` 동안 새 슬롯 요청을 막는다.
- 기본 재진입 대기시간은 1초이며 `DA_Enemy_Config`에서 조절한다.

### 피격과 사망

- 서버에서 Health 감소를 감지한다.
- 생존 피해를 받으면 `Staggered`, Health가 0이면 `Dead`로 전환한다.
- 피격 시 공격·회복을 취소하고 슬롯을 반납한다. 기본 경직 시간과 Hit React Montage 길이 중 긴 시간이 지난 뒤 추적을 재개한다.
- 사망 시 공격·이동을 중단하고 슬롯을 반납하며 AI Controller를 분리한다.
- 사망 0.2초 후 Capsule 충돌을 끄고, 기본 5초 후 Actor를 제거한다.
- `UBHEnemyAnimInstance`에서 `CombatState`, `bIsStaggered`, `bIsDead`를 사용할 수 있다.

### 애니메이션 연결 방식

`DA_Enemy_Config`의 Reaction 카테고리에 다음 항목을 추가했다.

| 항목 | 기본값 | 용도 |
|---|---:|---|
| `StaggerDuration` | 0.6초 | 경직 유지 시간 |
| `HitReactMontage` | None | 선택적 피격 Montage |
| `DeathMontage` | None | 선택적 사망 Montage |
| `DeathCollisionDisableDelay` | 0.2초 | 시체 Capsule 비활성화 시점 |
| `DeadActorLifeSpan` | 5초 | 시체 제거 시점, 0이면 유지 |
| `AttackSlotReentryDelay` | 1초 | 공격 종료 후 슬롯 재진입 대기 |
| `AttackMontageFailSafeGrace` | 0.5초 | 예상 공격 Montage 길이 이후 강제 회복까지의 여유 |

Montage를 사용하면 AnimGraph에 Montage가 사용하는 Slot 노드가 있어야 한다. Death Montage가 끝난 뒤 마지막 자세를 유지하려면 Montage의 자동 블렌드 아웃을 끄거나 `bIsDead` 기반 Dead 상태를 함께 구성한다.

## 작업 순서

### 1. 4마리 기준선 검증

- 넓고 평평한 테스트 구역에서 Enemy 4마리를 플레이어 사방에 배치한다.
- 네 적이 서로 다른 Attack Slot을 예약하고 접근하는지 확인한다.
- 공격 중인 적만 멈추고 나머지 이동이 계속되는지 확인한다.
- RVO가 꺼져 있고 Detour Crowd만 작동하는지 확인한다.

이 단계가 실패하면 적 수를 늘리지 않고 NavMesh, Capsule, 슬롯 반경, 공격 사거리부터 수정한다.

### 2. 최소 진단 정보 확인

다음 C++ 디버그 표시와 상태 전환 로그가 갱신되는지 확인한다.

- Enemy별 슬롯 종류와 인덱스
- 슬롯까지 남은 거리
- 이동 중 정체된 시간
- 마지막 슬롯 반납 사유
- 현재 전투 상태: 이동, 대기, 공격, 회복, 경직, 사망
- 실제 공격 시작 수와 동시 공격 상태 수
- 같은 층 Enemy Capsule 사이의 실제 중심 거리 위반 수

매 프레임 로그를 남기지 않고 상태가 변할 때만 기록한다. 포트폴리오용 정식 계측은 다음 단계에서 별도로 확장한다.

### 3. 8마리와 12마리 확장

- 8마리: Attack 4 + Wait 4 배치를 확인한다.
- 12마리: Attack 4 + Wait 8 전체 점유를 확인한다.
- 플레이어가 걷거나 방향을 바꿀 때 슬롯 목적지가 갱신되고 군중이 재배치되는지 확인한다.
- 플레이어가 이동해도 기존 슬롯 예약은 유지하고, 해당 슬롯의 월드 목적지만 갱신한다.
- 12마리를 초과한 적은 슬롯이 날 때까지 정지하되 공격하지 않는지 확인한다.

### 4. 통로 검증

Enemy Capsule 지름을 기준으로 두 종류의 통로를 만든다.

- 약 1.5배 폭: 한 줄 이동과 병목 확인
- 약 2.5배 폭: 교행과 추월 회피 확인

통로 입구, 출구, 플레이어 주변에 NavMesh 단절이나 지나치게 좁은 폴리곤이 없는지 먼저 확인한다. Crowd 설정은 현재 프로젝트 값을 기준선으로 기록한 뒤 한 항목씩만 조정한다.

### 5. 교착 감지와 복구 검증

AI가 슬롯으로 이동 중인데 목적지까지 거리가 의미 있게 줄지 않는 시간을 측정한다.

- 측정 주기: 기존 AI 갱신 주기와 같은 0.5초
- 정체 후보: 이동 상태인데 속도가 10 cm/s 미만이고 목적지 거리가 20 cm 이상 감소하지 않은 상태
- 정체 확정: 위 상태가 연속 2초 유지됨
- 경로 요청 자체가 실패하면 즉시 슬롯 반납
- 정체가 확정된 서버 갱신에서 현재 슬롯을 반납하고 재경로를 시작
- 실패한 슬롯은 해당 Enemy에게 2초 동안 재예약 금지
- 다른 슬롯을 요청하고 경로를 다시 계산
- 모든 후보가 실패하면 0.5초 뒤 재시도

정상적으로 줄을 서서 천천히 이동하는 경우와 실제 교착을 구분할 수 있도록 거리 감소량, 이동 상태, 속도를 함께 본다.

### 6. 사망·경직 반납 검증

#### 사망

- Enemy가 Health 0을 감지하면 Dead 상태로 전환한다.
- 공격 Montage와 회복 타이머를 중단한다.
- 이동과 공격을 비활성화하고 슬롯을 즉시 반납한다.
- Wait 적이 빈 Attack Slot으로 승격하는지 확인한다.

#### 경직

- Enemy에 Staggered 상태와 서버 권한 진입점을 추가한다.
- 경직 시작 시 현재 공격과 이동을 끊고 슬롯을 즉시 반납한다.
- 경직 종료 후 Chasing으로 돌아가 새 슬롯을 요청한다.
- 검증용 기본 경직 시간은 0.6초로 두되 데이터화하여 변경할 수 있게 한다.
- 1차 검증에서는 플레이어의 유효한 근접 공격 적중이 경직 진입점을 호출하게 한다. 경직 저항과 강인도 규칙은 후속 전투 기획으로 분리한다.
- 실제 피격 애니메이션 연결은 사용자가 에디터에서 담당한다.

사망 슬롯 반납은 Health 변경 콜백 안에서 처리한다. 경직 진입 시에도 같은 서버 호출 안에서 반납한다. 애니메이션이 없어도 상태와 슬롯 로직은 먼저 검증할 수 있다.

## Codex 작업

1. 최소 진단 정보와 슬롯 반납 사유 구현 완료
2. 2초 정체 watchdog과 실패 슬롯 재선택 구현 완료
3. 공격 회복 종료 후 슬롯 교대 구현 완료
4. Enemy 사망·경직 상태와 AI 슬롯 반납 구현 완료
5. Unreal 5.7 Editor Development 빌드 성공

## 사용자 에디터 작업

1. `DA_Enemy_Config`의 Reaction 항목을 확인한다.
2. 확보한 피격 Montage를 `HitReactMontage`, 사망 Montage를 `DeathMontage`에 지정한다.
3. 피격·사망 Montage가 사용하는 Slot 노드가 Enemy AnimBP의 AnimGraph에 있는지 확인한다.
4. 1차 군중 검증에서는 피격·사망 애니메이션의 Root Motion을 끈다. 위치 이동이 필요한 사망 연출은 슬롯 반납 검증 후 별도로 조정한다.
5. 공격 Montage는 반복 재생하지 않도록 설정하고, 서버에서 `PerformBasicAttackHit`를 호출하는 기존 Enemy Attack Hit Notify가 유지되는지 확인한다.
6. 사망 Montage 길이에 맞춰 `DeadActorLifeSpan`을 조절한다.
7. Enemy Character Movement의 `Use RVOAvoidance`를 끈다.
8. Crowd Manager의 `Max Agents`를 우선 32로 설정하고, `Max Agent Radius`가 Enemy Capsule 반지름보다 작지 않게 설정한다.
9. 아래 검증 순서대로 PIE를 실행한다.

## 현재 제한

- 피격·사망 상태는 복제되는 `EBHEnemyCombatState`로 구현했다. `State.Staggered`, `State.Dead` Gameplay Tag와 강인도 시스템은 후속 GAS 정리 범위다.
- 피격·사망 애니메이션 에셋은 아직 지정되지 않았으므로 Montage 재생과 최종 자세 유지는 PIE에서 확인해야 한다.
- 실패 슬롯 제외는 Enemy별 마지막 실패 슬롯 하나를 대상으로 한다. 여러 슬롯이 연속으로 실패하는 지형은 테스트 후 제외 목록 확장을 검토한다.
- 다층 지형에서 서로 다른 슬롯이 같은 NavMesh 위치로 투영되는 문제는 아직 보강하지 않았다.
- 이번 검증은 Standalone 또는 Listen Server 1인 기준이며 멀티클라이언트 표시는 후속 계측 단계에서 확인한다.

## 완료 조건

- 동시에 Attack Slot을 보유하는 적은 최대 4마리다.
- Wait Slot 보유자는 공격하지 않는다.
- 4, 8, 12마리 모두 넓은 장소에서 각자 예약 위치로 이동한다.
- 0.1초 간격 샘플에서 같은 층의 두 Enemy 중심 거리가 두 Capsule 반지름의 합보다 5 cm 이상 작으면 간격 위반으로 기록하며, 기준 테스트에서는 위반이 없어야 한다.
- 플레이어 이동 중 슬롯이 갱신되어도 영구 정지하는 적이 없다.
- 사망 또는 경직한 적은 해당 서버 상태 전환 호출 안에서 슬롯을 반납한다.
- 정체 조건이 2초 누적된 적은 다음 0.5초 갱신 안에 기존 슬롯을 반납하고 다른 슬롯 요청 또는 무슬롯 재시도 상태로 전환한다.
- 슬롯이 해제되면 Wait 적이 1초 안에 Attack Slot 승격을 시도한다.

## 검증 기록 방식

- 우선 범위는 1인 Standalone 또는 Listen Server PIE다. 멀티클라이언트 표시 검증은 포트폴리오 계측 단계에서 진행한다.
- 각 시나리오는 30초씩 3회 반복한다.
- 정지한 플레이어, 원형 이동, 통로 통과를 서로 다른 시나리오로 기록한다.
- 슬롯 상태 로그와 실제 공격 시작 로그를 대조하여 Wait 적의 공격 여부와 동시 공격 수를 확인한다.
- 코드가 보고하는 AI 상태만 믿지 않고, Actor 위치로 계산한 Capsule 간격과 상태 전환 시각을 함께 저장한다.
- 영상은 시각적 근거로 남기고, 합격 판정은 로그의 시간과 거리 수치를 사용한다.

## 진행 원칙

검증은 `4마리 넓은 장소 → 진단 정보 → 8마리 → 12마리 → 통로 → 교착 복구 → 사망·경직` 순서로 진행한다. 앞 단계가 통과되지 않으면 다음 단계의 Crowd 수치 튜닝으로 문제를 덮지 않는다.
