# 2026-08-28 - Enemy 전용 충돌 채널 구현

> 상태: 2026-08-29 롤백. 현재 명세는 [[몬스터 이동 시스템 규칙]]과 [[2026-08-29 - Enemy 이동 버벅임과 Formation Anchor 진단]] 참고.

## 목적

빠른 Pursuit와 Formation 이동 중 Enemy Capsule의 물리 Block과 Detour Crowd 회피가 동시에 개입해 발생하는 정지·밀림·방향 떨림을 줄인다.

## 구현 결과

### Collision Channel과 Profile

- `ECC_GameTraceChannel1`을 Object Channel `EnemyPawn`으로 등록했다.
- Capsule Profile `BHEnemyCapsule`을 등록했다.
- `EnemyPawn -> EnemyPawn`은 Ignore한다.
- `EnemyPawn -> Pawn`, WorldStatic, WorldDynamic은 Block한다.
- Collision Enabled는 `QueryAndPhysics`를 유지한다. Capsule 전체를 끄지 않는다.

### Enemy Capsule

- `ABHEnemy` 생성자와 BeginPlay에서 `BHEnemyCapsule` Profile을 적용한다.
- 기존 Enemy Blueprint가 과거 Capsule 기본값을 저장하고 있어도 BeginPlay에서 Object Type과 핵심 반응을 다시 적용한다.
- Pool 비활성화·사망 시에는 기존과 같이 Capsule을 끄며, 다시 활성화할 때 동일 Profile이 유지된다.

### Player Capsule

- Player는 기존 `Pawn` Object Type을 유지한다.
- Player Capsule은 `EnemyPawn`을 Block하도록 생성자와 BeginPlay에서 적용한다.
- 따라서 Enemy끼리는 통과할 수 있지만 Player와 Enemy는 서로 관통하지 않는다.

### Player 공격 판정

- 기존 공격 Sweep의 Object Query는 `ECC_Pawn`만 검색했다.
- `EnemyPawn`을 추가하여 Object Type 변경 뒤에도 최대 3명 타격과 기존 공격 판정이 유지되도록 했다.
- Enemy의 Committed Target Cone 공격은 예약된 Player를 직접 검증하므로 변경하지 않았다.

### Crowd 설정

- 이번 변경에서는 원인을 분리하기 위해 Detour Crowd 값을 바꾸지 않았다.
- Obstacle Avoidance와 Separation은 활성 상태다.
- Separation Weight `2.0`, Collision Query Range `500 cm`, Avoidance Range Multiplier `1.2`를 유지한다.

## 빌드 검증

- UE 5.7 UnrealHeaderTool 성공
- `BHEnemy.cpp`, `BHHeroCharacter.cpp` 컴파일 성공
- `UnrealEditor-ProjectBH.dll` 링크 성공
- 결과: `Succeeded`
- Visual Studio 14.38 비권장 경고만 있으며 컴파일 오류는 없다.

## 사용자 에디터 확인

Collision Channel과 Profile은 `DefaultEngine.ini` 시작 설정이므로 Unreal Editor를 완전히 종료했다가 다시 실행한다.

1. `Project Settings -> Engine -> Collision`에서 Object Channel `EnemyPawn`을 확인한다.
2. Preset 목록에서 `BHEnemyCapsule`을 확인한다.
3. PIE에서 Enemy끼리는 밀어내지 않고 Player와 벽은 여전히 Block하는지 확인한다.
4. Player 공격이 Enemy에게 정상적으로 적중하는지 확인한다.

기존 Enemy Blueprint Capsule의 표시가 과거 값이어도 런타임 C++이 Profile을 재적용한다. 다만 에디터 표시도 일치시키려면 Capsule의 Collision Preset을 `BHEnemyCapsule`로 지정해 저장해도 된다.

## PIE 검증 순서

1. 먼저 Crowd 값은 바꾸지 않고 12마리로 좁은 통로와 포위 상황을 시험한다.
2. 접촉 지점의 완전 정지·뒤로 튕김·방향 떨림이 감소했는지 확인한다.
3. Player와 벽 관통이 없는지 확인한다.
4. 한 공격에 최대 3명의 Enemy가 계속 피격되는지 확인한다.
5. 하드 끼임은 없어졌지만 너무 멀리서 감속하면 다음 단계에서 Separation Weight와 Query Range를 한 항목씩 튜닝한다.
