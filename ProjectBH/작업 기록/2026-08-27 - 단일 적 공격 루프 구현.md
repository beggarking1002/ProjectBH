# 2026-08-27 - 단일 적 공격 루프 구현

> 후속 변경: Enemy 공격 Montage와 수치는 더 이상 Blueprint에 직접 지정하지 않는다. 현재 설정 기준은 [[2026-08-27 - Enemy Data Asset 및 공격 정의 기반 구현]]이다. 아래 직접 필드 설명은 최초 프로토타입의 구현 이력으로 남긴다.

## 목적

단일 Enemy가 서버 권한으로 플레이어를 추적하고, 공격 거리에서 정지한 뒤 공격·회복을 거쳐 다시 추적 또는 재공격하는 최소 전투 루프를 만든다.

## 요청 이해

이번 작업은 다수 적 슬롯이나 Behavior Tree를 추가하는 단계가 아니다. 기존 `ABHCrowdEnemyAIController`의 단일 타깃 추적을 확장해 한 마리의 근접 Enemy가 `접근 → 정지 → 공격 → 회복 → 재공격`을 반복하고, 실제 피해 결과는 서버의 GAS를 통해 확정하는 범위로 이해했다. 공격 Montage와 AnimNotify의 에디터 배치는 사용자가 수행한다.

## Codex 변경 사항

- `EBHEnemyCombatState`를 추가하고 `Chasing`, `Attacking`, `Recovering` 상태를 Enemy Actor에서 복제한다.
- `ABHCrowdEnemyAIController`가 가장 가까운 플레이어를 추적하다가 Enemy의 `AttackStartRange` 안에 들어오면 이동을 멈추고 공격을 요청하도록 확장했다.
- 공격 중과 회복 중에는 Controller가 이동 명령을 다시 내리지 않는다.
- `ABHEnemy::TryStartBasicAttack`이 다음을 서버에서 수행한다.
  - 공격 대상을 한 공격 동안 고정한다.
  - 대상 방향으로 회전한다.
  - `Attacking` 상태로 전환한다.
  - 공격 Montage를 Reliable NetMulticast로 재생한다.
- Montage 종료 후 `Recovering` 상태에 들어가고 기본 0.75초 후 다시 `Chasing`으로 돌아간다.
- Montage가 중단돼도 종료 Delegate를 통해 Recovery로 넘어간다. Montage 재생 자체가 실패해도 즉시 Recovery로 복구한다.
- Montage가 지정되지 않았으면 공격 상태에 들어가지 않고 `cannot attack until EnemyAttackMontage is assigned` 경고를 한 번 남긴다.
- `BH Enemy Attack Hit` AnimNotify를 추가했다. Notify는 모든 머신에서 호출될 수 있지만 실제 타격 함수는 서버에서만 실행된다.
- 타격 순간 서버가 다음 조건을 다시 검사한다.
  - 수평 거리 225cm 이하
  - 높이 차이 120cm 이하
  - Enemy 전방 기준 좌우 60도 이내, 전체 120도 부채꼴
- 조건을 통과하면 전용 Instant Gameplay Effect로 플레이어 Health에 기본 10 피해를 적용한다.
- 한 공격에 Notify가 중복 호출되더라도 성공 피해는 한 번만 적용한다.
- 성공 시 서버 Output Log에 대상 Health 전후 값을 기록한다.

```text
Chasing
  → AttackStartRange 진입
  → Attacking / 이동 잠금 / Montage
  → BH Enemy Attack Hit / 서버 피해 검사
  → Montage 종료
  → Recovering 0.75초
  → Chasing / 재추적 또는 재공격
```

## 사용자 에디터 작업

### 1. 공격 Montage 생성

1. Guardian의 근접 공격 Animation Sequence를 선택한다.
2. 우클릭 후 `Create > Create AnimMontage`로 `AM_Guardian_Attack`을 만든다.
3. Montage가 반복 재생되지 않는지 확인한다.
4. 공격의 예고, 타격, 후속 동작이 한 Montage 안에서 끝나도록 범위를 구성한다.

현재 Git 저장소의 `/Game/Enemy`에는 Guardian 공격 Sequence가 포함되어 있지 않다. 사용자가 보유한 Guardian Skeleton 호환 근접 공격 Sequence를 선택해야 하며, 정확한 에셋 이름과 타격 시간은 선택한 애니메이션을 기준으로 기록한다.

### 2. ABP Slot 연결

`/Game/Enemy/Animation/ABP_Guardian`의 AnimGraph에서 Locomotion State Machine 뒤에 `Slot 'DefaultSlot'` 노드를 둔다.

```text
Locomotion State Machine
  → Slot(DefaultGroup.DefaultSlot)
  → Output Pose
```

Montage의 Slot도 `DefaultGroup.DefaultSlot`과 일치해야 한다.

### 3. 타격 Notify 배치

1. `AM_Guardian_Attack`의 Notify Track에서 손·무기·공격 부위가 플레이어에게 닿는 첫 프레임을 찾는다.
2. `Add Notify > BH Enemy Attack Hit`을 한 개 배치한다.
3. Compile/Save한다.

현재 `BH Enemy Attack Hit`은 `AnimNotify`다. 판정 상태를 켜는 시작 이벤트가 아니라, 배치된 프레임에 `PerformBasicAttackHit()`을 한 번 호출해 거리·높이·각도를 검사하고 즉시 종료하는 **단발 판정**이다. 따라서 대응하는 판정 종료 Notify는 필요하지 않다.

```text
Notify 도달
  → 서버 조건 검사 1회
  → 성공 시 피해 1회
  → 함수 종료
```

무기나 팔의 궤적이 여러 프레임 동안 유효해야 하는 공격으로 확장할 때는 `BH Enemy Melee Hit Window` 형태의 `AnimNotifyState`로 교체한다. 이 경우 `NotifyBegin`에서 판정 창과 이전 Trace 위치를 초기화하고, `NotifyTick`에서 연속 Sweep을 수행하며, `NotifyEnd`에서 판정 창과 중복 적중 집합을 정리한다. 현재 단일 대상·단일 충격 프레임 검증과는 서로 다른 판정 방식이다.

### 4. Enemy Blueprint 설정

`/Game/Enemy/BP_BHEnemy` Class Defaults의 `Combat > Enemy Attack`에서 다음을 설정한다.

- `Enemy Attack Montage`: `AM_Guardian_Attack`
- `Enemy Attack Damage Effect`: 기본 `BHGE_EnemyBasicAttackDamage`
- `Attack Start Range`: 150cm
- `Attack Hit Range`: 225cm
- `Attack Hit Half Angle`: 60도
- `Attack Hit Height Tolerance`: 120cm
- `Attack Recovery Duration`: 0.75초

공격 시작 거리보다 타격 거리를 75cm 크게 둔 것은 예고 동작 중 플레이어와 Enemy의 위치가 조금 달라져도 근접 공격이 지나치게 쉽게 빗나가지 않게 하는 첫 테스트용 관용 범위다. 실제 공격 애니메이션의 리치에 맞춰 이후 조정한다.

### 5. PIE 검증

1. NavMesh 위에 Enemy 한 마리를 둔다.
2. Enemy가 접근해 150cm 안에서 멈추는지 확인한다.
3. 공격 Montage와 Notify 이후 Output Log에 아래 형식의 로그가 나오는지 확인한다.

```text
EnemyName hit HeroName. Health: 100.0 -> 90.0
```

4. Montage 종료 후 0.75초 동안 움직이지 않고, 이후 플레이어가 멀면 추적하고 가까우면 재공격하는지 확인한다.
5. Output Log에서 카테고리 `LogProjectBH` 또는 문자열 `Health:`로 성공 로그를 찾는다.

### 6. 실패·음성 테스트

- 타격 Notify 전에 플레이어가 225cm 밖으로 빠지면 피해가 없어야 한다.
- Enemy 뒤쪽으로 이동하면 전방 부채꼴을 벗어나므로 피해가 없어야 한다.
- 같은 공격에 Notify를 임시로 두 개 배치해도 Health 감소는 한 번이어야 한다. 확인 후 Notify는 한 개로 되돌린다.
- `Enemy Attack Montage`를 비우면 Enemy는 공격 상태에 고착되지 않고 서버 로그에 Montage 미지정 경고가 한 번 나와야 한다.
- Montage를 강제로 중단해도 Recovery를 거쳐 다시 `Chasing` 상태로 돌아와야 한다.

### 7. Listen Server 검증 기준

PIE를 Listen Server와 Client 두 플레이어로 실행한다.

| 확인 항목 | 성공 기준 |
| --- | --- |
| 공격 연출 | 서버 창과 클라이언트 창 양쪽에서 같은 Enemy Montage가 보인다. |
| 피해 권한 | 서버 Output Log에 Health가 `100 → 90`으로 한 번만 감소한 기록이 남는다. |
| 속성 복제 | 클라이언트에서 조회한 플레이어 Health도 서버 결과와 동일하게 90이다. |
| 회복 잠금 | Montage 종료 후 0.75초 동안 Enemy가 이동·재공격하지 않는다. |
| 재개 | 회복 후 대상이 멀면 추적하고, 가까우면 다음 공격을 시작한다. |

현재는 Health 0 사망 시스템이 없으므로 Health가 0인 플레이어도 타깃 후보에서 자동 제외되지 않는다. 이는 다음 사망·타깃 무효화 작업에서 처리한다.

### 문제별 첫 점검 위치

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 공격 상태에 들어가지만 Montage가 안 보임 | ABP의 `DefaultSlot` 연결과 Montage Slot 이름 일치 |
| Montage 자체가 시작되지 않음 | `BP_BHEnemy`의 `Enemy Attack Montage` 지정과 Skeleton 호환성 |
| Montage는 보이지만 피해 없음 | `BH Enemy Attack Hit` Notify 위치, 거리·높이·전방 각도 |
| 서버 로그는 정상인데 클라이언트 Health가 다름 | GAS Attribute 복제 및 클라이언트에서 보고 있는 플레이어 인스턴스 |
| 공격 후 계속 멈춤 | Montage가 무한 반복인지, Montage 종료 Delegate가 호출될 수 있는 구성인지 |

## 검증

- UnrealHeaderTool 통과.
- `ProjectBHEditor Win64 Development` 빌드 성공.
- `git diff --check`에서 공백 오류 없음.
- 실제 Montage 재생과 PIE 서버 피해 검증은 사용자 에디터 연결 대기다.
- UE 공식 문서에서 Montage에 대응하는 AnimGraph Slot이 필요하고 Notify Track 이벤트가 애니메이션 시점에 실행되며 Instant Gameplay Effect가 즉시 Attribute를 변경하는 용도임을 대조했다.
