# Slot 추종 반응성과 거리 절감 교환

## 문제

1. Slot 위치가 변경된 뒤 Enemy가 잠시 멈춰 생각한 것처럼 늦게 반응했다.
2. Player 이동으로 Slot 위치가 교차했을 때 가까운 새 Slot으로 교환하지 않고 기존 Slot Index를 고집해 빙빙 도는 Enemy가 있었다.

## 원인

- AI의 정기 갱신은 기본 `0.5초 ± 0.15초`이며 역할별 목적지 재경로 임계값은 Attack `80 cm`, Wait `150 cm`, Holding/Pending `250 cm`였다.
- 기존 Formation Reform 코드는 있었지만 `ReformTriggerDistance = 0`으로 비활성화되어 있었다.
- 기존 Reform은 Ring 전체를 가까운 순서로 다시 배치하는 방식이라 그대로 활성화하면 집단 군무와 Slot 왕복이 재발할 위험이 있었다.

## 구현

- `ReformTriggerDistance` 기본값을 `75 cm`로 활성화했다.
- Player 현재 위치뿐 아니라 지연 추종하는 Engagement Anchor의 이동도 독립적으로 `75 cm`를 검사한다.
- 기준을 넘으면 모든 예약 Controller에 다음 프레임 갱신을 직접 통지한다. 기존 이동을 먼저 멈추지 않고 새 Move 요청으로 교체한다.
- Attack·Wait·Holding 계층과 현재 점유 Slot 집합은 유지한다.
- 같은 계층의 두 Enemy가 Slot을 교환했을 때 남은 이동거리 합이 최소 `75 cm` 줄어들 때만 교환한다.
- 가장 절감량이 큰 교환부터 적용하고 더 이상 기준을 넘는 조합이 없을 때 종료한다.
- 공격·회복 중인 Attack Enemy는 현재 Slot에 고정한다.
- Queue Sequence와 승격 우선권은 바꾸지 않는다.

## 기대 결과

- Player가 약 `75 cm` 움직인 시점에 Enemy들이 다음 프레임부터 새 Slot 경로를 사용한다.
- 서로의 새 Slot에 더 가까워진 두 Enemy는 명확한 이득이 있을 때 Slot을 교환한다.
- 작은 거리 차이에서는 기존 Slot을 유지해 대형 전체가 계속 자리를 바꾸는 현상을 막는다.

## 빌드

- UE 5.7 `ProjectBHEditor Win64 Development`: 성공

## PIE 검증

1. `bh.Debug.Slots 1`을 켠다.
2. Open에서 좌우로 `100~200 cm` 이동하고 Enemy의 재출발 지연을 확인한다.
3. 두 Enemy 사이를 가로질러 Slot 위치가 교차하게 이동한다.
4. 총 이동거리가 크게 줄어드는 경우 두 Enemy의 Slot Index가 교환되는지 확인한다.
5. 제자리에서 작은 왕복 이동을 반복해 Slot 소유권이 흔들리지 않는지 확인한다.
6. 공격·회복 중인 Enemy의 Attack Slot은 교환되지 않는지 확인한다.
7. Corridor와 Pocket에서도 같은 계층의 점유 수와 Queue 우선권이 유지되는지 확인한다.

## 에디터 확인

기존 Blueprint가 이전 C++ 기본값 `0`을 별도 저장하고 있다면 `BP_BHHeroCharacter > CombatEngagementSlots`에서 다음 값을 직접 확인한다.

- `Reform Trigger Distance = 75`
- `Reform Minimum Travel Saving = 75`
