# 2026-08-28 - 몬스터 압박감과 동기화 이동 진단

## 관찰된 문제

- 몬스터가 저돌적으로 추격하지 않고 플레이어 주변에서 눈치를 보며 자리를 맞추는 것처럼 보인다.
- 플레이어가 이동하면 모든 몬스터가 동시에 같은 방향으로 이동해 추격보다 단체 군무처럼 보인다.

## 코드 기준 원인

1. AI Controller가 상태와 관계없이 항상 Player를 Focus하므로 Ring을 따라 이동할 때 진행 방향 대신 Player를 보며 옆걸음한다.
2. 첫 `0.5초` 동안 모든 Enemy를 Wait/Holding에 임시 배정한 뒤 Attack 네 명을 고르므로 초기 돌진이 늦다.
3. Attack 진입도 `ApproachRing -> AlignOnRing -> Ingress`를 거치며 `1도` 각도와 `5 cm` Waypoint 수용 반경을 맞춰 지나치게 정밀하다.
4. 모든 Slot 위치가 Player의 현재 위치에서 계산된다. AI도 동일한 `0.5초` 간격으로 갱신되고 Slot이 `50 cm` 움직이면 재경로하므로 Player 이동에 집단이 거의 동시에 반응한다.
5. Player가 `500 cm` 이동하면 Attack을 제외한 각 Ring 예약을 한 번에 재배치하므로 큰 이동에서는 동기화가 더 강해진다.
6. 이동 상태별 속도가 없고 모든 상황에서 Enemy Config의 단일 `MaxWalkSpeed` 기본 `300 cm/s`를 사용한다.

## 개선 방향 초안

### 1. 추격과 포위 진입 분리

- 전투권 밖 Enemy는 Slot을 즉시 맞추지 않고 Player의 이동 방향을 고려한 추격 목표로 달린다.
- 전투권 안에 들어온 Enemy만 Attack/Wait/Holding Formation에 참여한다.
- 초기 Attack 네 명은 Wait 정렬을 거치지 않고 즉시 Attack 진입 경로를 받는다.

### 2. 상태별 방향과 속도

- Pursuit, Approach, Align에서는 이동 방향을 바라본다.
- Ingress와 Attack 직전에만 Player를 바라본다.
- Pursuit와 Attack 진입은 빠르게, Wait/Holding 선회는 상대적으로 느리게 설정한다.

### 3. Player 이동 반응 비동기화

- Attack Enemy는 Player 이동에 빠르게 반응한다.
- Wait/Holding은 Player의 현재 위치가 아니라 일정 거리 뒤따르는 Engagement Anchor를 기준으로 한다.
- Enemy마다 재경로 임계값과 짧은 결정 지연을 분산해 같은 프레임의 집단 방향 전환을 막는다.
- 작은 Player 이동에는 현재 목표를 유지하고, Anchor가 이탈 반경을 넘었을 때만 목표를 갱신한다.

### 4. 정밀 Formation 완화

- Ring 우회는 Combat Core를 실제로 가로지르거나 통로 교착 위험이 있을 때만 사용한다.
- 진입 각도와 Waypoint 수용 반경을 전투 연출에 맞게 완화한다.
- `500 cm` 이동 시 전체 재편성 대신 한 번에 한 명씩 또는 Ring별 시간차를 두고 재배치한다.

## 권장 구현 순서

1. 상태별 Focus와 이동속도를 분리한다.
2. 초기 Attack 네 명을 즉시 돌진시킨다.
3. Wait/Holding용 Engagement Anchor와 이동 Dead Zone을 추가한다.
4. Enemy별 재경로 시간차를 추가한다.
5. 전체 Reform을 점진적 Reform으로 바꾼다.
6. Ring 진입 정밀도를 완화하고 PIE에서 압박감과 겹침을 함께 조정한다.
