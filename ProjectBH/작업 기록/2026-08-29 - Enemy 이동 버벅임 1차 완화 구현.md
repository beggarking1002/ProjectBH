# Enemy 이동 버벅임 1차 완화 구현

> 상태: C++ 구현과 `ProjectBHEditor Win64 Development` 빌드 완료. PIE 체감 검증 대기. 정식 규칙은 [[몬스터 이동 시스템 규칙]]을 기준으로 한다.

## 목적

영상 분석 전에 현재 코드에서 확인된 두 유력 원인을 먼저 완화한다.

1. Path Following의 즉시 속도 변경과 Slot 도착 시 강제 정지가 Capsule 이동을 끊을 가능성
2. Enemy ABP의 원시 `bHasAcceleration` 조건이 Crowd 조향 중 Idle/Jog를 흔들 가능성

이번 수정은 원인 확정이 아니라 두 가설을 검증 가능한 형태로 줄이는 1차 조치다.

## 구현

### 가속 기반 Path Following

관련 코드: `Source/ProjectBH/AI/BHCrowdEnemyAIController.cpp`

- 모든 Enemy 이동 의도를 적용할 때 `bUseAccelerationForPaths`를 켠다.
- `bRequestedMoveUseAcceleration`도 켜서 CharacterMovement의 가속·제동을 사용한다.
- 기존 Pursuit·Attack·Wait·Holding 속도와 Move 재요청 거리 정책은 유지한다.
- 실제 감속 곡선은 Enemy CharacterMovement의 `MaxAcceleration`, `BrakingDecelerationWalking`, Ground Friction 설정에 의존한다. 이번 작업에서는 이 값들을 바꾸지 않았다.

### Slot 최종 도착 조건

관련 코드: `Source/ProjectBH/AI/BHCrowdEnemyAIController.h`, `Source/ProjectBH/AI/BHCrowdEnemyAIController.cpp`

- 위치 조건: 예약 Slot에서 `20 cm` 이내
- 속도 조건: 수평 속도 `5 cm/s` 이하
- 두 조건을 모두 만족해야 `StopMovement()`와 Attack 시작 검사를 수행한다.
- 위치 조건만 만족하고 아직 빠르게 이동 중이면 새 0거리 Move를 요청하지 않고 자연 감속을 기다린다.
- Wait·Holding·Pending은 감속이 끝날 때까지 진행 방향을 유지하고, 최종 정지 뒤 Player Focus로 전환한다.

### Enemy 이동 상태 히스테리시스

관련 코드: `Source/ProjectBH/AnimInstance/BHEnemyAnimInstance.h`, `Source/ProjectBH/AnimInstance/BHEnemyAnimInstance.cpp`

- `bShouldMove` 추가
- 정지 상태에서 `GroundSpeed >= 10 cm/s`: 이동 진입
- 이동 상태에서 `GroundSpeed <= 5 cm/s`: 정지 진입
- 5~10cm/s 구간에서는 이전 상태를 유지한다.
- 기존 Enemy ABP가 참조하는 `bHasAcceleration`을 Enemy에서만 `bShouldMove`와 같게 제공한다. 따라서 이번 1차 시험을 위해 사용자가 ABP를 즉시 수정할 필요는 없다.
- Hero AnimInstance의 `bHasAcceleration` 의미는 변경하지 않았다.

`bHasAcceleration` 호환 연결은 현재 Idle/Jog 전환을 즉시 안정화하기 위한 임시 호환책이다. Enemy ABP의 다른 그래프에서도 이 값을 가속 그 자체로 사용한다면 의미가 달라질 수 있다. PIE에서 다른 참조가 확인되면 해당 전환을 `bShouldMove`로 교체한 뒤 호환 연결을 제거한다.

Slot `20 cm`, 정지 `5 cm/s`, 이동 상태 `10/5 cm/s`는 1차 검증값이다. 체감만으로 확정하지 않고 동일 조건 반복 결과를 본 뒤 조정한다.

## 변경하지 않은 것

- Detour Crowd와 Separation 설정
- Enemy Capsule Collision
- Slot 수, 승격, Queue 규칙
- Pursuit·Formation 목표 갱신 거리
- Animation Blueprint와 Blend Space 에셋

## 빌드 검증

- UnrealHeaderTool 성공
- `BHEnemyAnimInstance.cpp`, `BHCrowdEnemyAIController.cpp` 컴파일 성공
- `UnrealEditor-ProjectBH.dll` 링크 성공
- 결과: `Succeeded`
- 기존 Visual Studio 14.38 비권장 Toolchain 경고 외 신규 경고·오류 없음

## PIE 확인 순서

대상은 `UBHEnemyAnimInstance`를 부모로 쓰고 `ABHCrowdEnemyAIController`에 Possess된 Enemy다. 현재 플레이 맵의 동일한 Player·Enemy 스폰 위치와 설정을 유지하고, 정지 플레이어와 이동 플레이어 시나리오를 각각 `30초 × 3회` 확인한다.

1. `show collision`을 켜고 정지 플레이어 주변으로 진입하는 Enemy Capsule을 본다.
2. Slot 직전 Capsule이 순간 정지·재출발하지 않고 한 번의 감속으로 멈추는지 확인한다.
3. Capsule은 매끄러운데 Mesh만 끊기는 Enemy가 남는지 확인한다.
4. 한 번의 이동 시작·정지 구간에서 Idle → Jog → Idle 전환이 한 번씩만 발생하는지 Animation Debugger 또는 영상 프레임으로 확인한다.
5. 플레이어가 이동할 때 8~12마리로 같은 검증을 반복한다.
6. 실패 장면은 Enemy 한 마리의 Capsule, 발, Slot 디버그, 이동 시작·종료가 한 화면에 나오도록 남긴다.

수동 영상은 1차 판정 자료다. 디버그 문자열이 스스로 출력한 상태만으로 성공을 판정하지 않으며, 최종 합격 근거와 독립 계측 원칙은 [[몬스터 이동 시스템 규칙#28.4 측정 방식]]을 따른다. 이번 작업에서는 별도 자동 계측을 추가하지 않았다.

## 판정과 다음 조치

- Capsule과 Mesh가 모두 개선: 두 원인이 함께 증상을 만들었을 가능성이 높다.
- Capsule만 개선: Anim State 전환 Duration과 Blend Space 보간을 다음으로 확인한다.
- Mesh만 개선: Move 요청 완료·중단, `StopMovement()` 호출과 실제 Velocity를 시간축으로 계측한다.
- 둘 다 개선되지 않음: Detour Crowd의 회피 속도 샘플과 애니메이션 재생 속도 불일치를 포함해 영상 기반으로 재진단한다.
