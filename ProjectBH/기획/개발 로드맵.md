# ProjectBH 개발 로드맵

## 현재 상태 (2026-08-27)

- UE 5.7.4 C++ 프로젝트다.
- Third Person 템플릿과 `Variant_Combat` 예제 기반의 전투 코드가 있다.
- 기존 전투 코드에는 콤보, 차지 공격, 피격, 적, 스포너의 참고 구현이 있으나, ProjectBH의 온라인 코옵용 복제·서버 권한 구조는 아직 없다.
- 따라서 기존 `Variant_*` 코드는 기능 참고 자료로 취급하고, 새 게임 시스템은 ProjectBH의 요구에 맞는 명확한 구조로 구축한다.
- 검방 캐릭터의 서버 권한 근접 타격과 CombatDummy 피해 연결을 검증했다.
- `ABHEnemy`와 `UBHEnemyAnimInstance`를 추가했다. `ABHEnemy`는 Detour Crowd AI Controller, Attack/Wait Slot, 서버 권한 공격·경직·사망 상태를 사용한다.
- 군중 적의 실제 전역 경로는 UE NavMesh, 근거리 회피는 Detour Crowd를 사용한다. ProjectBH가 직접 구현할 차별화 영역은 전투 슬롯, 동시 공격 제한, 대기열, 벽 등반 레인 예약이다.

## 네트워크 Ground Rule (2026-08-22)

- ProjectBH는 **리슨 서버 기반 온라인 코옵 게임**으로 개발한다.
- 첫 검증은 호스트 1명과 클라이언트 1명의 2인 세션이며, 성공 후 최대 4인으로 확장한다.
- 체력, 피해, 적 AI, 스폰, 웨이브와 승패 같은 게임플레이 결과는 서버가 최종 권한을 가진다.
- 클라이언트는 이동·공격 등의 입력 의도를 보내며, 서버 검증 없이 게임플레이 결과를 확정하지 않는다.
- 애니메이션, 사운드, 카메라 흔들림 같은 연출은 복제된 결과를 바탕으로 각 클라이언트에서 재생한다.

## 첫 번째 마일스톤: 2인 코옵 전투 수직 슬라이스

목표는 리슨 서버와 클라이언트가 함께 다음을 검증할 수 있는 최소 플레이 루프를 만드는 것이다.

1. 두 플레이어가 같은 테스트 맵에 접속하고 서로의 이동·회전을 확인한다.
2. 양쪽 플레이어가 검을 장비하고 기본 2타 공격을 사용한다.
3. 공격 판정과 피해는 서버가 처리하고, 피격·사망 결과가 모든 클라이언트에 복제된다.
4. 적 더미 또는 단일 일반 몬스터를 대상으로 전투를 반복한다.

### 이 순서를 우선하는 이유

- ProjectBH의 핵심 차별점은 코옵 액션 전투이므로, 공격 판정과 피해 권한을 나중에 네트워크화하면 재작업 비용이 크다.
- 클래스, 퍽, 보조장비, 웨이브는 이 전투 루프가 검증된 뒤 데이터 구조 위에 확장할 수 있다.
- 현재 존재하는 전투 예제를 그대로 확장하면 싱글플레이어 전제와 이름·의존성이 남을 수 있으므로, 필요한 아이디어만 재사용한다.

## 권장 구현 순서

1. **프로젝트 기반 정리**: Git 초기 커밋과 Git LFS 규칙을 준비하고, 게임 전용 C++ 폴더·명명 규칙을 만든다.
2. **네트워크 전투 기반**: 플레이어 캐릭터, 체력/피해 컴포넌트, 서버 권한 공격 RPC, 복제 상태를 구현한다.
3. **검 1종**: 기본 2타 콤보, 애니메이션 노티파이 기반 타격 판정, 적 더미 피격을 연결한다.
4. **플레이 테스트 맵**: 사용자가 에디터에서 테스트 맵, 블루프린트 파생 클래스, 입력·애니메이션 연결을 구성한다.
5. **일반 몬스터 1종**: 서버 주도 AI 추적·공격·사망을 추가한다.
6. **웨이브 최소 루프**: 스폰, 처치 수, 웨이브 완료/실패, 간단한 HUD를 구현한다.
7. **확장 단계**: 장비 데이터, 가드·강공격·퍼펙트 가드, 클래스 패시브·궁극기, 퍽, 엘리트 몬스터 순으로 확장한다.

## 현재 구현 순서: 군중 몬스터 전투 수직 슬라이스

아래 순서는 앞 단계의 검증 결과가 다음 단계의 전제 조건이 되도록 구성한다. 한 번에 다수 적·슬롯·벽 등반을 구현하지 않는다.

### 1. 단일 적 NavMesh 추적 — C++ 완료, 에디터 검증 대기

- Codex 완료: `ABHCrowdEnemyAIController`를 만들고, 서버에서 가장 가까운 플레이어를 획득해 `MoveToActor`를 요청하는 최소 추적 흐름을 구현했다.
- 사용자: 테스트 맵에 `NavMeshBoundsVolume`과 `BP_Enemy_Base` 하나를 배치하고, `bWalkLeftForAnimationPreview`를 끈다.
- 완료 조건: 서버와 클라이언트에서 적 한 마리가 NavMesh 위를 따라 플레이어의 정지 거리까지 이동하고, Enemy AnimBP의 이동 Blend Space가 재생된다.

### 2. 단일 적 공격 루프 — C++ 완료, 에디터 검증 대기

- Codex 완료: 공격 거리 진입, 추적 정지, 공격 Montage, 타격 Notify, 회복 상태와 서버 권한 GAS 피해를 구현했다.
- 사용자: 적의 임시 공격 Montage와 AnimNotify를 연결한다.
- 완료 조건: 한 마리가 접근·정지·공격·회복을 반복하고, 서버에서만 피해가 확정된다. 플레이어 사망과 추적 중단은 후속 범위다.

### 3. Combat Engagement Slot

- Codex 완료: 플레이어에 `UCombatEngagementSlotComponent`를 추가하고 Attack Ring 4개와 Wait Ring 8개의 생성, 예약, 반납, 디버그 표시를 구현했다.
- 사용자 진행: 플레이어 Blueprint에서 컴포넌트를 확인하고 디버그 화면을 검증한다.
- 완료 조건: 4마리가 플레이어가 아닌 예약 위치로 이동하며, 한 번에 Attack Slot 수보다 많은 적이 공격하지 않는다.

### 4. Detour Crowd 군중 검증

- Codex 완료: 슬롯 실패·사망·경직 시 반납, 정상 공격 회복 후 Attack Slot 지속 점유, 500 cm 이동 Reform, 실패 슬롯 재선택, 2초 교착 watchdog, 피격·사망 애니메이션 진입점을 구현했다.
- 사용자 진행: Crowd Manager와 Enemy Capsule 설정을 조정하고, RVO가 꺼져 있는지 확인한 뒤 4→8→12마리 순서로 PIE를 검증한다.
- 완료 조건: 8~12마리가 넓은 장소와 좁은 통로에서 Capsule 겹침 없이 접근하고, 막힌 적은 2초 안에 대기 슬롯 또는 재경로 상태로 복구한다.

### 5. 포트폴리오 계측 및 비교

- Codex: 슬롯, 예약자, AI 상태, 공격 권한을 화면에 표시하고 필요한 지표를 기록한다.
- 사용자: 일반 `MoveTo(Player)` 방식과 슬롯 방식의 비교 영상을 캡처한다.
- 완료 조건: 동시 공격 수, 대기 시간, 겹침·교착 횟수의 전/후 근거가 남는다.

### 6. 벽면 Traversal

- Codex: `ATraversalWallLink`의 Smart Nav Link 연동, 레인 예약, `MOVE_Custom` 이동을 구현한다.
- 사용자: 벽 지오메트리와 Link의 Entry/Exit를 배치하고 등반 애니메이션을 연결한다.
- 완료 조건: 단일 적 등반을 먼저 검증한 뒤, 4개 레인으로 8마리가 대기·등반·상단 전투 슬롯 합류를 수행한다.

## 지금 할 일

**4마리 기준선부터 Detour Crowd와 Combat Slot의 에디터 런타임 검증을 진행한다.**

C++ 구현과 UE 5.7 Editor 빌드는 완료했다. 테스트 맵에서 4마리 기준선을 통과한 뒤 8마리, 12마리, 통로, 플레이어 이동, 경직·사망, 교착 유도 순서로 확장한다. 피격·사망 애니메이션은 `DA_Enemy_Config`의 Reaction 항목과 Enemy AnimBP의 상태 값에 연결한다.
