# 몬스터 이동 시스템 조작 및 수치 치트시트

> ProjectBH 몬스터 이동 시스템을 PIE에서 확인하거나 튜닝할 때 자주 쓰는 항목만 모은 문서다.  
> 기준일: 2026-08-30

이 문서의 수치는 C++ 기본값과 [[몬스터 이동 시스템 규칙]]의 현행 설계값을 요약한 것이다. Blueprint Class Defaults나 레벨 인스턴스에서 값을 덮어썼다면 에디터에 표시되는 override가 실제 실행값이다. 값을 변경할 때는 코드 또는 기준 문서를 먼저 수정하고 이 치트시트를 함께 갱신한다. 과거 작업 기록의 `Attack Slot 4개` 같은 값은 당시 이력이지 현행값이 아니다.

## 0. 테스트 전 사전 확인

- 엔진 기준: `Unreal Engine 5.7`
- 시스템 검증용 맵: `/Game/Maps/FeatureDevMap`
- 맵에 `NavMeshBoundsVolume`, `BP_BHEnemyPoolManager`, Player Start가 있어야 한다.
- Pool Manager의 `Spawn Points`가 비어 있으면 자동 검색 가능한 `TargetPoint`가 맵에 있어야 한다.
- 디버그를 볼 때는 아래 세 인스턴스의 Draw Debug 설정을 미리 켠다.
  - `/Game/Enemy/BP_BHCrowdEnemyAIController`: `Draw Crowd Debug`
  - `/Game/PlayerCharacter/BP_BHHeroCharacter`의 `CombatEngagementSlots`: `Draw Debug Slots`
  - `/Game/Enemy/ObjectPool/BP_BHEnemyPoolManager`: `Draw Pool Debug`

## 1. 가장 자주 쓰는 확인 순서

1. 레벨 뷰포트에서 `P`를 눌러 초록색 NavMesh가 필요한 이동 구역을 모두 덮는지 확인한다.
2. `Alt + P`로 PIE를 시작한다.
3. 게임이 마우스를 잡고 있으면 `Shift + F1`로 에디터 커서를 되찾는다.
4. `~` 키로 콘솔을 열고 다음 명령을 입력한다.

```text
bh.Debug.Enabled 1
bh.Debug.Slots 1
bh.Debug.Crowd 1
bh.Debug.Pool 1
```

5. 테스트가 끝나면 `Esc`로 PIE를 종료한다.

## 2. 알아둘 단축키

| 단축키 | 용도 | 주의사항 |
| --- | --- | --- |
| `P` | NavMesh 표시 On/Off | 레벨 에디터 뷰포트에 포커스가 있을 때 사용한다. |
| `Alt + P` | 현재 Play 설정으로 PIE 시작 | 시작 위치는 Play 설정에 따라 Camera Location 또는 Player Start다. AI 검증은 Player Start가 안전하다. |
| `Esc` | 뷰포트 PIE 종료 | 게임 입력이 Esc를 소비하는 경우 `Shift + F1`로 커서를 되찾고 툴바의 Stop을 누른다. |
| `Shift + F1` | PIE에서 마우스 제어를 에디터로 반환 | 콘솔 입력이나 Actor 선택 전에 유용하다. |
| `F10` | 뷰포트 PIE에서 Eject/Possess 전환 | 플레이어 조작에서 빠져나와 실행 중 Actor와 디버그 표시를 관찰할 때 쓴다. |
| `~` | 게임 콘솔 열기 | 프로젝트의 `DefaultInput.ini`에 `ConsoleKeys=Tilde`로 설정되어 있다. 한글 입력 상태에서는 안 열릴 수 있으므로 영문 입력으로 전환한다. |
| `Ctrl + Shift + S` | Save All | Montage·Animation Sequence·Blueprint를 수정한 뒤 자주 사용한다. |
| `Ctrl + Alt + F11` | Live Coding 빌드 | 구조체·UCLASS·컴포넌트 구성 변경은 에디터 재시작과 전체 빌드가 더 안전하다. |

단축키는 `Edit → Editor Preferences → Keyboard Shortcuts`에서 변경할 수 있다.

## 3. ProjectBH 전용 콘솔 명령

### 3.1 전체 디버그

| 명령 | 결과 |
| --- | --- |
| `bh.Debug.Toggle` | 전체 디버그 표시 상태 반전 |
| `bh.Debug.Enabled 1` | 전체 디버그 허용 |
| `bh.Debug.Enabled 0` | 전체 디버그 차단 |

### 3.2 종류별 디버그

| 명령 | 결과 |
| --- | --- |
| `bh.Debug.Crowd 1` | Enemy 머리 위 상태와 이동 경로 표시 |
| `bh.Debug.Crowd 0` | Crowd 표시 끄기 |
| `bh.Debug.Slots 1` | Slot·Ring·Anchor·공간 분석·간격 진단 표시 |
| `bh.Debug.Slots 0` | Slot 표시 끄기 |
| `bh.Debug.Pool 1` | Enemy Pool 상태 표시 |
| `bh.Debug.Pool 0` | Pool 표시 끄기 |

Master와 개별 항목이 모두 `1`이어야 화면에 나온다. 또한 아래 인스턴스 설정도 켜져 있어야 한다.

- `BP_BHCrowdEnemyAIController`: `Draw Crowd Debug`
- `BP_BHHeroCharacter`의 `CombatEngagementSlots`: `Draw Debug Slots`
- 레벨의 `BP_BHEnemyPoolManager`: `Draw Pool Debug`

콘솔 명령은 인스턴스에서 꺼 둔 Draw Debug 설정을 강제로 켜지는 못한다.

### 3.3 엔진 보조 진단 명령

| 명령 | 용도 |
| --- | --- |
| `stat fps` | 현재 FPS 확인 |
| `stat unit` | Game·Draw·GPU 프레임 시간 확인 |
| `showdebug AI` | 언리얼 기본 AI 디버그 HUD On/Off |
| `ai.crowd.DebugSelectedActors 1` | 선택한 Crowd Agent의 상세 Detour 디버그 활성화 |
| `ai.crowd.DebugSelectedActors 0` | 상세 Crowd 디버그 종료 |
| `ai.crowd.DrawDebugNeighbors 1` | 선택 Agent의 이웃 관계 표시 |
| `ai.crowd.DrawDebugPath 1` | 선택 Agent의 Crowd 경로 표시 |
| `ai.crowd.DrawDebugVelocityObstacles 1` | 회피 속도 샘플 표시 |

`ai.crowd.*` 상세 표시는 항상 켜 두지 말고, Detour Crowd 원인을 좁힐 때만 사용한다.

선택한 Enemy 하나를 깊게 볼 때의 순서:

1. PIE를 시작하고 `F10`으로 Eject한다.
2. `Shift + F1`로 마우스를 되찾아 월드의 Enemy를 하나 선택한다.
3. 콘솔에서 `ai.crowd.DebugSelectedActors 1`을 입력한다.
4. 필요에 따라 `ai.crowd.DrawDebugNeighbors 1`, `ai.crowd.DrawDebugPath 1`, `ai.crowd.DrawDebugVelocityObstacles 1`을 켠다.
5. 확인 후 켠 항목을 모두 `0`으로 되돌린다.

## 4. 디버그 표시 읽는 법

### Slot 색

| 역할 | 빈 Slot | 점유 Slot |
| --- | --- | --- |
| Attack | 초록 | 빨강 |
| Wait | 청록 | 노랑 |
| Holding | 파랑 | 보라 |
| Pending | 청록과 초록 사이의 작은 구체 | 별도의 실제 예약 Slot은 없음 |

그 밖의 표시:

- Combat Core: 주황색 원
- Engagement Anchor: 지연 추종은 청록, 중앙 복귀는 노란 구체와 Player 연결선
- Capsule 간격 위반: 자홍색 선
- 이동 단계: Direct 흰색, ApproachRing 청록, AlignOnRing 파랑, Ingress 주황
- Corridor: Player 양쪽의 보라색 방향 화살표

### Player 위 집계

- `A`: Attack 점유 수/활성 수
- `W`: Wait 점유 수/전체 수
- `H`: Holding 점유 수/전체 수
- `Q`: Pending 수
- `Phase`: Initial 또는 Runtime
- `Revision`: 대형 재편 버전
- 실제 공격 중인 Enemy 수
- Attack Slot 밖에서 공격 중인 규칙 위반 수
- 현재·최대 간격 위반 수

### Enemy 위 상태

- Combat State
- 이동 Mode: Pursuit, InitialCharge, Formation
- Target과 유지 시간
- Slot Type·Index와 Queue Sequence
- Slot까지 거리와 현재 속도
- Facing: `Move` 또는 `Target`
- Route Stage
- 누적 Stuck 시간
- Formation Revision과 마지막 Slot 반납 사유

### 5.2 공격 거리 연동

| 항목 | 현재값 | 위치 |
| --- | ---: | --- |
| Guardian Attack Start Range | `150 cm` | `DT_AttackDefinition`의 공격 행 |
| Attack Ring Radius | `125 cm` | Hero의 `CombatEngagementSlots` |
| Slot Acceptance Radius | `20 cm` | `BP_BHCrowdEnemyAIController` |
| 안전한 Slot 중심 최대 거리 | `130 cm` | `150 - 20` 계산값 |
| Combat Core Radius | `100 cm` | Hero의 `CombatEngagementSlots` |

Attack Ring을 키울 때는 반드시 다음 관계를 지킨다.

```text
AttackRingRadius ≤ AttackStartRange - SlotAcceptanceRadius
현재: 125 ≤ 150 - 20 = 130
```

Attack Ring만 `130 cm`보다 크게 만들면 Slot에는 도착했는데 공격 거리 검사에서 탈락할 수 있다. `CombatCoreRadius`의 실제 유효값도 `AttackRingRadius - 5 cm`를 넘지 않도록 제한된다.

### 5.8 Corridor와 Pocket 대형

| 항목 | Corridor | Pocket |
| --- | ---: | ---: |
| Agent 반경/Slot 간격 | `45 cm / 95 cm` | `95 cm` Slot 간격 |
| 행 간격 | `100 cm` | `100 cm` |
| 계층 간 빈 공간 | `100 cm` | 해당 없음 |
| Wait·Holding Row 최대 Lane | Row당 `4개` | 해당 없음 |
| Row 횡단면 검사 폭 | 좌우 `350 cm` | 해당 없음 |
| Row NavMesh 투영 허용 오차 | `35 cm` | 해당 없음 |
| Row 구조 확정 대기 | `0.35초` | 해당 없음 |
| 반대 Side 추가 검색 Row | `6개` | 해당 없음 |
| Attack 후보 검사 | `360° / 16방향` | 열린 방향 중심 `80°` |
| Attack 후보 벽 여유 검사 | `8방향 × 45 cm` | 해당 없음 |
| Attack 후보 최소 간격 | `90 cm` | `95 cm` |
| Combat Core 우회 반경 | 기본 `160 cm` | 적용 안 함 |
| 우회 waypoint 각도 | 최대 `45°` | 적용 안 함 |
| 우회 waypoint 투영 허용 오차 | `35 cm` | 적용 안 함 |
| 방향 Follow Alpha | `0.35` | `0.35` |
| 방향 변경 재경로 각도 | `15°` | `15°` |

Corridor Attack은 Ring 전체 `16개` 후보를 검사한다. NavMesh 투영 허용 오차는 `35 cm`, 후보 간 최소 간격은 `90 cm`, 수용량 확정 대기는 `0.3초`다. 전체 활성 수는 `0~5명`이며 공격·회복 중에는 현재 후보 조합과 해당 Enemy의 Slot Index를 유지한다. Side·채널은 선호값이며 같은 Side에서 도달 가능한 Enemy가 없으면 반대 Side를 허용한다. Combat Core를 가로지르는 경로는 기본 `160 cm` 우회 Ring에서 양방향 동적 waypoint를 비교한다. Wait·Holding·Pending은 각 Row의 실제 횡단 폭으로 `1~4 Lane`을 다시 계산한다. 양쪽 수용량이 충분하면 Wait `4:4`, Holding `8:8`을 우선하며, 한쪽이 먼저 전체 수를 채워도 `6개` 추가 Row까지 반대쪽을 검색한다. Row Lane 조합은 `0.35초` 유지된 뒤 확정한다. Corridor에서 가까운 경계가 `100 cm 이하`이고 반대쪽 여유가 `100 cm 이상 더 크면` Pocket으로 들어간다. 해당 Pocket 유지 기준은 `130 cm 이하 / 여유 차이 60 cm 이상`이다. Mouth는 전방·후방을 각각 판정하며 `Raw`가 `0.3초` 연속되면 Corridor 내부 `MouthMixed`에 들어간다. `Held 0.5초`는 이탈 유예에만 쓰고, Side0·Side1·Double 종류 변경은 다른 Raw가 `0.6초` 연속될 때 확정한다. 단일 Mouth는 보라색 Corridor Row와 주황색 Open Fan을 함께 사용하고, Double Mouth는 양쪽 Fan을 사용한다. 단발성 Player NavMesh 투영 실패는 `0.6초` 동안 마지막 확정 대형을 유지한다. 디버그에서는 `AttackCand:유효/전체`, `Selected`, `ActiveA`, `Edge:가까운 거리/+반대쪽 여유 차이`, `Mouth F:Raw/Held/No 폭 R:Raw/Held/No 폭 Mixed:현재 Next:후보 시간`, `AttackLanes`, `RowLanes`, `RowSides W:A/B H:C/D`와 두 번째 줄의 `Layout / Assigned / TargetQ / NearTarget`을 확인한다. 기본 배치는 `RowSides W:4/4 H:8/8`이다. 탈락 Attack 후보는 어두운 빨강, 유효한 미선택 후보는 흰색이다. Combat Core는 주황색, 우회 Ring은 보라색이며 양·음 회전 Move Goal은 자홍색·보라색이다. Mouth 단면은 평소 하늘색, Raw는 빨간색, Held는 주황색이다.

Pocket의 Attack은 `125 cm` 첫 Row만 사용하며 열린 호에 `95 cm` 간격으로 실제 들어가는 수만 활성화한다. 전체 상한은 5개지만 기본 최대 반각 `80도`에서는 최대 4개다. Wait·Holding·Pending만 공간이 부족할 때 `100 cm` 바깥의 다음 Row를 사용한다.

### 5.9 Object Pool

조정 위치: 레벨에 배치한 `BP_BHEnemyPoolManager`

| 항목 | 현재값 |
| --- | ---: |
| Pool Capacity | `40` |
| Active Enemy Limit | `12` |
| Respawn Delay | `5초` |
| Minimum Corpse Display Time | `5초` |
| Fallback Spawn Spacing | `175 cm` |
| Spawn Nav Projection Extent | `(100, 100, 300) cm` |
| Spawn Point 자동 검색 | `On` |
| 반복 Spawn Point 분산 | `On` |

시체는 5초 뒤 자동 삭제되는 구조가 아니다. 최소 5초는 반드시 보여 주고, 비활성 여분 Enemy가 없어 새 Enemy를 내보낼 수 없을 때 가장 오래된 적격 시체부터 회수한다.

`Project Settings → Engine → Crowd Manager → Max Agents`는 `Active Enemy Limit`보다 크게 둔다. 현재 프로젝트는 `12`가 활성 상한이므로 최소 12보다 커야 하며, 테스트 여유까지 고려해 설정한다. `Max Agent Radius`는 가장 큰 Enemy Capsule 반지름 이상이어야 한다.

기본 `Active Enemy Limit = 12`에서는 Holding 16칸 전체와 30번째부터의 Pending을 재현할 수 없다. Pending 검증 전용 테스트에서만 `Active Enemy Limit ≥ 30`, `Pool Capacity ≥ Active Enemy Limit`, `Crowd Manager Max Agents > Active Enemy Limit`로 임시 조정하고, 검증 후 원래 값으로 되돌린다.

## 8. 안전한 튜닝 루프

1. 한 번에 변수 하나만 바꾸고 변경 전 값을 메모한다.
2. Blueprint·DataTable·레벨 인스턴스의 override 여부를 확인한다.
3. C++이면 빌드하고, Asset이면 저장한 뒤 PIE를 완전히 다시 시작한다.
4. 같은 위치·같은 Enemy 수·같은 Player 이동으로 전후를 비교한다.
5. 개선되지 않으면 원래 값으로 복구한다. 연동 수치는 6장의 표를 함께 확인한다.
