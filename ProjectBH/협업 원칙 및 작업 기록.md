# ProjectBH 협업 원칙 및 작업 기록

이 문서는 새 채팅에서 빠르게 프로젝트 맥락과 협업 방식을 복원하기 위한 기준 문서다.

## 작업 기록 원칙

- ProjectBH의 모든 작업 내역은 이 옵시디언 볼트(`ProjectBH/`)에 Markdown 파일로 남긴다.
- 새 기능, 시스템 변경, 주요 조사 및 의사결정은 작업이 끝난 뒤 별도 기록 문서에 정리한다.
- 기록은 다음 대화를 맡는 AI가 바로 이해할 수 있도록 목적, 변경 사항, 관련 파일, 검증 결과, 남은 작업 순서로 작성한다.
- 기존 문서를 변경하는 경우에도 중요한 설계 변경이나 결정은 작업 기록 문서에 남긴다.
- 게임 기획 문서와 기획 초안은 `기획/`에, 완료된 작업의 이력은 `작업 기록/`에 분리해 보관한다.

## 역할 분담

### Codex (AI)

- C++ 코드, 설정 파일, 데이터 구조, 빌드 오류 분석 및 자동화 가능한 프로젝트 파일 작업을 직접 수행한다.
- 각 요청에서 코드 작업을 마친 뒤, 사용자가 언리얼 에디터에서 직접 수행해야 하는 블루프린트·에셋·맵 작업을 구체적인 순서로 분리해 안내한다.
- 블루프린트 작업을 임의로 대신 진행하거나, 에디터 내부 조작이 완료되었다고 가정하지 않는다.
- 작업 완료 전에는 가능한 범위에서 빌드 또는 관련 검증을 수행하고 결과를 기록한다.

### 사용자

- 언리얼 에디터 내부의 블루프린트 작성·연결, 에셋 설정, 맵 배치 등 에디터 중심 작업을 수행한다.
- Codex가 안내한 에디터 작업의 완료 여부와 발생한 오류를 공유한다.

## 작업 요청 처리 방식

1. 요청의 목표와 기존 구조를 확인한다.
2. Codex가 담당할 코드 및 파일 변경을 구현한다.
3. 사용자가 수행할 언리얼 에디터 작업을 체크리스트로 제공한다.
4. 구현 내용과 검증 결과를 옵시디언 작업 기록에 남긴다.

## 작업 기록 문서 형식

새 작업 기록은 `작업 기록/` 폴더에 다음 형식을 따른다.

```md
# YYYY-MM-DD - 작업 제목

## 목적

## Codex 변경 사항

## 사용자 에디터 작업

## 검증

## 관련 파일

## 남은 작업 / 다음 단계
```
