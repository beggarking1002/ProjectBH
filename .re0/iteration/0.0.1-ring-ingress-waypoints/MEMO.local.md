# Re0 Memo

## 학습

### 경로 위상이 잘못되면 회피 강도로 해결할 수 없다

사용자 재현에서 Detour Crowd의 조향 설정을 강화한 후에도 이동 Enemy가 정지한 Slot 점유자 사이에서 끼었다. Local Avoidance는 주어진 이동 목표를 수행하는 보조 계층이며, 목표 진입로가 점유자로 닫혔다면 공간을 새로 만들지 못한다.

**다음 게이트:** Crowd 튜닝 전에 목표 생성이 정지 점유자 레이어를 관통하는지 먼저 Debug한다.

### 중앙 진입점보다 슬롯별 분산형 진입로가 필요하다

이전 Gate 실패는 여러 Enemy의 다른 최종 목표를 하나의 중간 목표로 압축해 새로운 병목을 만든 사례다. 분산형 Ring Ingress는 최종 Slot 각도를 중간 목표에도 보존한다.

**반패턴:** 여러 레인의 문제를 하나의 공유 Gate로 해결하는 수렴 병목.

**다음 게이트:** 중간 목표가 에이전트별 최종 목표의 각도를 보존하는지 검증한다.

### 경로 단계는 시각화되어야 한다

단순한 `Moving/Stuck`만으로는 어느 단계에서 교착이 생겼는지 구분할 수 없다. Route Stage 텍스트와 색상별 경로선은 다음 PIE 검증에서 원인을 `Approach`, `Align`, `Ingress`, `Direct`로 분리한다.

**다음 게이트:** 새 이동 정책은 성공/실패만이 아니라 중간 의사결정 상태를 런타임에서 관찰할 수 있어야 한다.

## 보존할 것

- Attack/Wait/Holding 예약과 중앙 승격 순서
- Wait 22.5도, Holding 11.25도 오프셋으로 만든 방사형 통로
- Detour Crowd의 국소 회피와 Stuck Watchdog
- Gate 롤백 문서를 음성 코퍼스로 유지

## 버릴 것

- Separation Weight를 계속 높이면 정지 점유자로 닫힌 진입로를 해결할 수 있다는 가정
- 모든 Attack 진입자가 하나의 Gate를 공유하는 설계

## 사이클 판정

**현재 판정: iterate in place.** 코드·빌드·문서 게이트는 통과했지만 UE Editor 4/8/12/13+마리 실행 게이트가 남았다. PIE에서 교착이 충분히 줄면 현 모듈을 유지한다. 같은 지점에서 물리 캡슐 교착이 남으면 코드를 더 넓히기 전에 `EnemyPawn` 전용 충돌 채널을 독립 실험한다. 현 사이클에서 `re0-work`는 필요하지 않다.
